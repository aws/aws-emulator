# EC2 refusal messages are emulator-authored prose instead of AWS's wording across ten refusal families (10 causes)

> _Note: this issue was identified against the code base at commit `abd75e982d55cd9e91541cb3d125feb2d8edb60f`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
AcceptTransitGatewayPeeringAttachment

## Description
Ten root causes, each a refusal whose HTTP status and error code are right but whose message text is the emulator's own sentence. An error message is a requirement: clients log it, match it and show it to operators. In every cause below the fixed text is wrong; only the ids/values interpolated into it come from the request or state.

Cause 1 of 10: transit-gateway-attachment absence. AWS: `Transit Gateway Attachment <attachmentId> was deleted or does not exist.` — fixed prefix 'Transit Gateway Attachment ', the attachment id from the request, fixed suffix ' was deleted or does not exist.' Emulator: `The transit-gateway-attachment ID '<attachmentId>' does not exist`. Why: a client cannot tell 'deleted' from 'never existed' and message-matching breaks. Fix: the transit-gateway attachment resolution helper shared by Accept/Reject/Describe. Traces: ec2.op-contract-acceptTransitGatewayPeeringAttachment, ec2.op-contract-acceptTransitGatewayPeeringAttachment-b, ec2.op-contract-acceptTransitGatewayVpcAttachment-b, ec2.op-contract-reject-transit-gateway-vpc-attachment-rejected.

Cause 2 of 10: invalid CIDR in the BYOIP/prefix plane. AWS: `The CIDR (<value>) is not valid.` Emulator: `Invalid value '<value>' for Cidr. It must be an IPv4 or IPv6 address range in CIDR notation`; and for ProvisionByoipCidr `Value (<value>) for parameter cidr is invalid. This is not a valid CIDR block.` Fix: the CIDR parser's refusal message in the BYOIP handlers. Traces: ec2.op-contract-advertiseByoipCidr, ec2.op-contract-advertiseByoipCidr-b, ec2.op-contract-provision-byoip-cidr-rejected.

Cause 3 of 10: malformed CIDR in a security-group rule. AWS: `CIDR block <value> is malformed` (the value unquoted, no member path). Emulator: `CIDR block '<value>' of ipPermissions.1 is malformed` — adds quoting and an ipPermissions index AWS does not emit here. Fix: AuthorizeSecurityGroupIngress' rule validation message. Traces: ec2.op-malformed-security-group-cidr-rejected.

Cause 4 of 10: malformed resource-id messages use a generic template. AWS: for an ENI id, `The interface ID '<id>' is malformed`; for an AMI id in RestoreImageFromRecycleBin the AWS wording is likewise resource-specific. Emulator: the generic `Invalid id: "<id>"` for both. Fix: the per-resource malformed-id message templates in the id validation layer. Traces: ec2.op-contract-assignIpv6Addresses-b, ec2.op-contract-restore-image-from-recycle-bin.

Cause 5 of 10: duplicate security-group rule names the generated rule id instead of the rule. AWS: `the specified rule "peer: <cidr>, <protocol>, from port: <from>, to port: <to>, <ALLOW|DENY>" already exists` — the rule's own tuple, taken from the request. Emulator: `the specified rule "sgr-..." already exists`, i.e. the emulator's generated rule id, which the caller never sent and cannot correlate. Fix: AuthorizeSecurityGroupIngress' duplicate-rule message construction. Traces: ec2.op-contract-authorize-security-group-ingress.

Cause 6 of 10: placement-group absence on double delete. AWS refuses the second DeletePlacementGroup with the message ending in a period and AWS's own code; the emulator answers `InvalidPlacementGroup.Unknown` with `The Placement Group '<name>' is unknown.` for a case AWS words differently (and the sibling already-exists path drops AWS's trailing period: AWS `The placement group '<name>' already exists.` vs emulator `... already exists` ). Fix: the placement-group handlers' message table. Traces: ec2.op-contract-delete-placement-group.

Cause 7 of 10: wrong-state wording. AWS: `Route Server Peer <peerId> is in an invalid state.` Emulator: `route-server-peer '<peerId>' is in the 'deleted' state.` Likewise EnableVolumeIO on a volume already enabled: the emulator answers IncorrectState with `The I/O operations of volume '<volumeId>' are already enabled, so there is nothing to enable`, which is not AWS's text for this refusal class. Fix: the route-server-peer and volume-IO handlers' state-refusal messages. Traces: ec2.op-contract-delete-route-server-peer, ec2.op-contract-enable-volume-io, ec2.enable-volume-io-recovers-error-state.

Cause 8 of 10: overlap/conflict wording carries extra interpolated ids. AWS: `Reservation CIDR <cidr> has overlap with existing reserved CIDR block`; the subnet-overlap family is worded without naming the colliding resource id. Emulator: `Value (<cidr>) for parameter cidr is invalid. The CIDR overlaps the existing subnet CIDR reservation '<scrId>'.` and `The CIDR '<cidr>' conflicts with another subnet ('<subnetId>')`. Fix: the subnet-CIDR-reservation and subnet-overlap validation messages. Traces: ec2.op-contract-delete-subnet-cidr-reservation.

Cause 9 of 10: pagination-token, filter-name and absence messages in the Describe plane. AWS: the InvalidPaginationToken message is AWS's exact sentence, not `Next token '<token>' is invalid`; an invalid filter is `Value (<name>) for parameter Filter is invalid. ` (note AWS's trailing space) not `The filter '<name>' is invalid`; a filter-name enumeration must list the allowed names in AWS's order (`[status, path-found]`), not sorted (`[path-found, status]`); VPC-endpoint absence and capacity-reservation-cancellation-quote malformed messages likewise diverge. Fix: the Describe* pagination/filter validation messages and their value ordering. Traces: ec2.op-contract-describe-capacity-reservation-topology, ec2.op-contract-describe-transit-gateway-attachments, ec2.op-contract-describe-vpc-endpoints, ec2.op-contract-describe-capacity-reservation-cancellation-quotes-duplicate, ec2.describe-network-insights-analyses-contract.

Cause 10 of 10: per-operation validation sentences that restate the rule in the emulator's own words. AWS wording differs for: CopyVolumes undersized target (emulator: `Invalid value '<n>' for size. The size must be equal to or greater than the size of the source volume, which is <n> GiB`), CreateCustomerGateway bgpAsn range (emulator: `Value (<n>) for parameter bgpAsn is invalid. Valid values: 1 to 2147483647.`), CreateVpcBlockPublicAccessExclusion with neither target (emulator: `Either 'subnetId' or 'vpcId' must be specified`), AttachVolume zone mismatch (AWS: `The volume '<volId>' is not in the same availability zone as instance '<instanceId>'`; emulator: `The volume '<volId>' is in availability zone '<az>' and the instance '<instanceId>' is in availability zone '<az>'`), ModifySubnetAttribute with two attributes (emulator: `Only one attribute can be modified at a time, and this request names <members>. Use separate requests for each attribute.`), AssociateIpamByoasn CIDR absence (emulator: `The CIDR (<cidr>) could not be found in IPAM.`). Fix: those operations' validation messages. Traces: ec2.copy-volumes-undersized-target-rejected, ec2.create-customer-gateway-contract, ec2.check-create-vpc-block-public-access-exclusion-missing-target-rejected, ec2.op-volume-attach-zone-mismatch-fails, ec2.op-contract-modify-subnet-attribute, ec2.op-contract-associate-ipam-byoasn.
