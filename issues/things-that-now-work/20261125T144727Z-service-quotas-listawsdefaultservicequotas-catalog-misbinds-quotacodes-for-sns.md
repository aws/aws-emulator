# service-quotas ListAWSDefaultServiceQuotas catalog misbinds QuotaCodes for sns sqs sso storagegateway timestream vpc vpc-lattice wafv2 workspaces xray

> _Note: this issue was identified against the code base at commit `b9452e21b4cf2c09e703f5517f289577e00d07ce`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
TEN causes in this bundle (Cause 1 of 10 .. Cause 10 of 10), all one shared fault in the same place: the default-quota catalog that backs ListAWSDefaultServiceQuotas. For ten more ServiceCode values the catalog (a) omits rows AWS publishes, (b) returns a row with `Description` absent, and (c) binds a QuotaCode to a NEIGHBOURING quota's metadata, so `QuotaName`, `Description`, `Value`, `Unit`, `Adjustable`, `Period` and `UsageMetric` all describe a different quota than the `QuotaCode` names. All ten replay with HTTP 200 on both sides -- the status and the envelope are right, only the catalog content is wrong.

Shared AWS grounding (applies to every cause below). Smithy: ListAWSDefaultServiceQuotas(ServiceCode required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$) -> ListAWSDefaultServiceQuotasResponse{Quotas: ServiceQuotaListDefinition, NextToken}. Smithy shape ServiceQuota members: QuotaCode (@length 1..128, the quota's identifier), QuotaName, QuotaArn, Value (QuotaValue double @range 0..10000000000), Unit, Adjustable (boolean, default false), GlobalQuota, Description (QuotaDescription @length 0..350), Period -> QuotaPeriod{PeriodValue:integer, PeriodUnit:enum}, UsageMetric -> MetricInfo{MetricNamespace, MetricName, MetricDimensions (map @length 0..10), MetricStatisticRecommendation @pattern ^(Sum|Maximum)$}, QuotaContext. The model documents QuotaCode as "the quota identifier" and the other members as the facts about THAT quota, so the requirement is a per-QuotaCode binding: a row keyed L-xxxxxxxx must carry the name, description, value, unit, adjustability, period and usage metric of the quota that code identifies, and the response must contain every default quota AWS publishes for the requested ServiceCode. The model says nothing about which codes exist for a given ServiceCode or what their values are -- for those, recorded behavior only (the recorded 200 response body for each ServiceCode below is the expectation). AWS returns 200 with no error for all of these requests; no error code or message is involved.

Shared Emulator behaviour: for each ServiceCode below the emulator answers 200 but the Quotas list is shorter than AWS's and its rows are shifted/re-labelled -- the data appears to be assembled from a differently ordered or differently keyed source than the QuotaCode index, with Description (and sometimes Period/UsageMetric/QuotaContext) simply not populated.

Shared Why: Service Quotas is a lookup API. A client that asks for a quota by code (capacity planners, limit-increase tooling, Terraform/CDK quota checks, CloudWatch usage-metric wiring built from UsageMetric.MetricDimensions) receives a value and a name belonging to a different quota, or no row at all. Decisions are then made against the wrong limit -- e.g. an SQS client told the in-flight-standard-queue quota is 20 instead of 120000, or a Timestream client told tables-per-account is 1 instead of 50000. Rows whose Description is absent break UIs and docs generators that render it, and a missing row makes a real quota look nonexistent.

Shared Fix: the ListAWSDefaultServiceQuotas handler's default-quota catalog (the per-ServiceCode seed/state table it serves from) -- the rows for these ten service codes must be re-keyed so every field hangs off the correct QuotaCode, the omitted rows added, and Description/Period/UsageMetric/QuotaContext populated for every row. This is not a serializer problem: the shapes serialize fine, the stored rows are wrong.
