# appconfig__lambda: the AT_DEPLOYMENT_TICK extension action point never invokes its Lambda, so a ROLL_BACK directive is ignored and the deployment completes anyway

> _Note: this issue was identified against the code base at commit `8c5ca24b773ca2762f91097a2e2db632761ff691`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
StartDeployment

## Description
Cause 1 of 1 — an AppConfig extension association whose AT_DEPLOYMENT_TICK action point targets a Lambda is never invoked during a rollout, so the directive the function returns can never steer the deployment. Failing check id: appconfig__lambda.at-deployment-tick-directive-rollback-reverts-the-deployment.

AWS: Smithy (appconfig): ActionPoint enum includes AT_DEPLOYMENT_TICK alongside PRE_CREATE_HOSTED_CONFIGURATION_VERSION, PRE_START_DEPLOYMENT, ON_DEPLOYMENT_START, ON_DEPLOYMENT_STEP, ON_DEPLOYMENT_BAKING, ON_DEPLOYMENT_COMPLETE, ON_DEPLOYMENT_ROLLED_BACK; CreateExtension.Actions binds an Action (Name, Uri, RoleArn) to each point, and DeploymentEvent carries EventType (DeploymentEventType: PERCENTAGE_UPDATED, ROLLBACK_STARTED, ROLLBACK_COMPLETED, BAKE_TIME_STARTED, DEPLOYMENT_STARTED, DEPLOYMENT_COMPLETED, REVERT_COMPLETED), TriggeredBy, Description (@length 0..1024) and ActionInvocations. For AT_DEPLOYMENT_TICK the documented contract (recorded behavior only, as the model does not shape the invocation payload or the response) is: while a non-instant deployment is in progress AppConfig assumes the action's RoleArn and synchronously invokes the target Lambda once per tick, passing an event that names the deployment (DeploymentNumber), the Environment under deployment and the rollout position (PercentageComplete); the function's response body selects the next step via a Directive of CONTINUE or ROLL_BACK with an accompanying Description. A ROLL_BACK directive makes the deployment terminate in state ROLLED_BACK (DeploymentState ROLLED_BACK), log both ROLLBACK_STARTED and ROLLBACK_COMPLETED EventLog entries and NOT log DEPLOYMENT_COMPLETED, carry the Description the extension returned in the EventLog entry text, attribute the ROLLBACK_STARTED entry's TriggeredBy to the extension rather than the caller (recorded behavior only: the recorded value is EXTENSION, which the modeled TriggeredBy enum — USER, APPCONFIG, CLOUDWATCH_ALARM, INTERNAL_ERROR — does not list), and revert the data plane so AppConfigData serves the previously deployed configuration version's exact bytes again. A subsequent StopDeployment on that terminal deployment is refused with HTTP 400 BadRequestException whose message is the fixed template "Deployment <n> for App <applicationId> and Environment <environmentId> cannot be stopped, it has a status of <state>." — the fixed words are "Deployment", "for App", "and Environment", "cannot be stopped, it has a status of" and the final period, while the deployment number, application id, environment id and state are values from the request and the emulator's state.

Emulator: from the replay output, the AT_DEPLOYMENT_TICK target is never invoked at all. The control leg — an identical deployment whose tick function returns Directive=CONTINUE and forwards every event it receives to an observation SQS queue — reaches COMPLETE, but nothing is ever delivered to that queue, and the check fails at the first tick observation with AssertionError: "the AT_DEPLOYMENT_TICK action point never invoked the Lambda — nothing reached the observation queue, so no tick was routed through the extension". Because no tick is dispatched, none of the downstream behavior can occur either: a deployment ticked with ROLL_BACK is not rolled back, no ROLLBACK_STARTED/ROLLBACK_COMPLETED entries appear, the extension's Description never reaches the EventLog, and the data plane is never reverted. The extension itself is accepted (CreateExtension round-trips the AT_DEPLOYMENT_TICK action's Uri, and CreateExtensionAssociation binds it to the environment ARN), so the association looks live while being inert — an over-permissive accept.

Why: a client that uses an AT_DEPLOYMENT_TICK extension as its rollout safety control gets the exact opposite of the guarantee it bought. Its handler is never consulted, its ROLL_BACK directive is silently discarded, and the bad configuration version rolls out to 100% and stays in service; the deployment record reports COMPLETE, so neither the EventLog nor the deployment state reveals that the guard never ran. Automation that treats a successful CreateExtensionAssociation as proof the guard is armed will ship unguarded deployments.

Fix: the AppConfig extension action-point dispatch inside the deployment-progress/tick engine — the per-tick invoke of the associated Lambda (assume RoleArn, build the tick event with DeploymentNumber, Environment and PercentageComplete, invoke synchronously) and the handling of its response Directive in the deployment state machine: honoring ROLL_BACK by driving the deployment to ROLLED_BACK, appending ROLLBACK_STARTED/ROLLBACK_COMPLETED EventLog entries carrying the returned Description with TriggeredBy attributed to the extension, suppressing DEPLOYMENT_COMPLETED, and reverting the served configuration in the AppConfigData data-plane state. Related open issues cover the OTHER action points and the tick event's shape but not this one: 20261105T111951Z-appconfig-lambda-appconfig-extension-action-points-never-invoke.md (PRE_START_DEPLOYMENT / ON_DEPLOYMENT_START / PRE_CREATE_HOSTED_CONFIGURATION_VERSION dispatch), 20261027T010737Z-appconfig-lambda-backed-extension-action-points-still-never.md, and 20261107T182959Z-appconfig-lambda-the-at-deployment-tick-extension-event.md (tick event omits PercentageComplete).

## Evidence
Expected (real AWS): the CONTINUE control deployment's tick target is invoked, so the observation queue receives a tick event naming the deployment (DeploymentNumber == the deployment under test), the Environment under deployment (Environment.Id == the environment id) and the rollout position (a PercentageComplete key); the second, identical deployment whose tick answers Directive=ROLL_BACK terminates with State == "ROLLED_BACK", its EventLog contains both ROLLBACK_STARTED and ROLLBACK_COMPLETED and no DEPLOYMENT_COMPLETED, a ROLLBACK_STARTED entry's Description carries the text the extension returned and its TriggeredBy attributes the rollback to the extension (not the caller), the data plane serves the previous version's exact bytes again on a fresh configuration session, and StopDeployment on that terminal deployment is refused 400 BadRequestException "Deployment <n> for App <applicationId> and Environment <environmentId> cannot be stopped, it has a status of <state>."

Actual (emulator): the control deployment reaches COMPLETE but nothing is ever delivered to the observation queue, i.e. the action point fired zero times. Replay output:

CreateExtension accepted the AT_DEPLOYMENT_TICK action and round-tripped its Uri, and CreateExtensionAssociation bound it to the environment ARN, so the inert association is indistinguishable from an armed one. All ROLL_BACK-directive behavior downstream of the tick (ROLLED_BACK state, the two rollback EventLog entries, the extension-supplied Description, the extension attribution, the data-plane revert) is therefore unobservable.

## Steps to Reproduce
1. Create an SQS observation queue, an IAM execution role allowing sqs:SendMessage to it, and a Python Lambda whose handler forwards every event it receives to that queue and returns {"Directive": os.environ["DIRECTIVE"], "Description": os.environ["REASON"]}; start it with DIRECTIVE=CONTINUE. Add a lambda:InvokeFunction permission for principal appconfig.amazonaws.com, and create a second role trusted by appconfig.amazonaws.com that may invoke the function.
2. CreateExtension with Actions={"AT_DEPLOYMENT_TICK": [{"Name": "steer", "Uri": <function ARN>, "RoleArn": <appconfig invoke role ARN>}]}.
3. CreateApplication, CreateEnvironment, CreateConfigurationProfile(LocationUri="hosted"), and two hosted configuration versions (v1, v2). CreateExtensionAssociation binding the extension to the environment ARN.
4. CreateDeploymentStrategy with DeploymentDurationInMinutes=2, GrowthFactor=25, GrowthType=LINEAR, FinalBakeTimeInMinutes=0 (a non-instant strategy — a 0-minute deployment invokes no action point at all).
5. StartDeployment of v1 and wait for a terminal state. Then long-poll the observation queue: on AWS a tick event arrives carrying DeploymentNumber, Environment.Id and PercentageComplete; on the emulator nothing ever arrives.
6. Flip the function's DIRECTIVE to ROLL_BACK, StartDeployment of v2, wait for terminal: expect State ROLLED_BACK with ROLLBACK_STARTED/ROLLBACK_COMPLETED in the EventLog, the returned Description present, TriggeredBy attributed to the extension, the data plane serving v1's bytes again, and StopDeployment on it refused 400 BadRequestException with the "...cannot be stopped, it has a status of <state>." message.
