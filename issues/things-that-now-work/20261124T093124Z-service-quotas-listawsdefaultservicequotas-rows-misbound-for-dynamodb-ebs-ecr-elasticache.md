# ListAWSDefaultServiceQuotas rows misbound for dynamodb ebs ecr elasticache elasticfilesystem elasticloadbalancing

> _Note: this issue was identified against the code base at commit `cb1793cf7c5a4b5a69e7dca7c8a291b52f4b88d5`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
SIX causes, one per ServiceCode. They share one fault: the emulator's default-quota catalog for these service codes binds a row's payload (QuotaName, Description, Value, Unit, Adjustable, Period, UsageMetric.MetricDimensions) to the WRONG QuotaCode, and where the QuotaCode/QuotaName pairing is right the Description is a paraphrase rather than the text AWS publishes. Every call returns HTTP 200 with a well-formed ServiceQuota list, so no status or error code diverges — the defect is entirely in the row contents.

Shared AWS behavior (Smithy: ListAWSDefaultServiceQuotas, input ServiceCode required, output Quotas -> ServiceQuotaListDefinition of ServiceQuota; ServiceQuota members QuotaCode @length 1-128 @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$, QuotaName, Description @length 0-350, Value -> QuotaValue double @range 0-10000000000, Unit, Adjustable (default false), GlobalQuota (default false), UsageMetric -> MetricInfo, Period -> QuotaPeriod). QuotaCode is documented as the quota's identifier — AWS returns, for each QuotaCode, THAT quota's name, description, value, unit, adjustability, period and usage metric. The Description text itself is a fixed, service-published string per QuotaCode (recorded behavior for the exact wording; the model only constrains its length). The contract this pass checks is the QuotaCode -> (QuotaName, Description, Value, Unit, Adjustable, Period, UsageMetric) pairing and the exact Description text, not any per-run value; this response carries no ids, timestamps or request-scoped values at all.

Why (all causes): a client reads default quotas by QuotaCode — to display the quota, to compare an applied value against the default, or to decide whether to call RequestServiceQuotaIncrease. When the emulator returns another quota's name/value under a QuotaCode, the client silently reasons about the wrong quota: it shows a wrong limit (e.g. 100 instead of 100000 snapshots per Region), concludes a quota is or is not adjustable wrongly, and any assertion on Description or QuotaName against AWS's published text fails. Because the status is 200 the client has no signal anything is wrong.

Fix (all causes): the service-quotas default-quota catalog that backs the ListAWSDefaultServiceQuotas handler — the static per-ServiceCode quota table in the service-quotas crate (services/service-com-amazonaws-servicequotas-servicequotasv20190624). The rows must be re-keyed so each QuotaCode carries its own quota's metadata, and each Description must carry AWS's published string verbatim instead of a paraphrase. This is catalog data, not serialization: the envelope and member names are already correct.
