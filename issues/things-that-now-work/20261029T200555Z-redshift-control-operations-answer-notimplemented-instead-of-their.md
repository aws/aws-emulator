# Redshift control operations answer NotImplemented instead of their modeled refusals: ModifyClusterDbRevision, PauseCluster, EnableLogging, ModifyAquaConfiguration, ModifyLakehouseConfiguration, the scheduled-action family and GetIdentityCenterAuthToken (7 causes)

> _Note: this issue was identified against the code base at commit `5b71589754f95f05f88c1a0ee9ccd691bbc5f701`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
PauseCluster

## Description
Seven distinct root causes, all in the redshift service, all with the same shape: the operation's handler is a scaffold that answers error code `NotImplemented` (message "operation <X> is scaffolded but not implemented in this emulator") instead of performing the operation or raising the error AWS models for the request. Each cause is a different handler/operation family and must be closed separately. The open issue 20261024T024248Z-redshift-cluster-scoped-credential-and-notification-operations-answer.md covers a neighbouring set of cluster-scoped NotImplemented handlers (RebootCluster, ResumeCluster, GetClusterCredentialsWithIAM, EnableLogging's bucket-POLICY leg, ...); the causes below are the ones its replay keys do not carry and name additional contracts the stood-up handlers must satisfy.

Cause 1 of 7: ModifyClusterDbRevision does not resolve the cluster. AWS: the ClusterIdentifier is looked up first and a nonexistent one fails ClusterNotFoundFault. Smithy (com-amazonaws-redshift-redshiftserviceversion20121201): ModifyClusterDbRevision errors = ClusterNotFoundFault (errorKind client, httpError 404, awsQueryError code `ClusterNotFound`, 404), ClusterOnLatestRevisionFault, InvalidClusterStateFault, UnsupportedOperationFault. The message is the cluster-not-found template whose fixed text is "Cluster " ... " not found." with the requested ClusterIdentifier filled in from the request. Emulator: error code `NotImplemented`. Why: a client that branches on ClusterNotFound to decide "create it" vs "patch it" cannot branch, and SDK retry classifiers treat the unmodelled code as an unknown non-retryable failure rather than a 404. Fix: the ModifyClusterDbRevision handler in the redshift ops directory — resolve the cluster from service state and raise ClusterNotFoundFault before any revision logic. Traces: redshift.cluster-scoped-triaged-ops-not-found-semantics.

Cause 2 of 7: PauseCluster does not enforce cluster state. AWS: PauseCluster is legal only from an active/available cluster; pausing a cluster still in `creating` fails InvalidClusterStateFault with the fixed message "You can only pause an ACTIVE Cluster" (no variable parts), and the identical call succeeds once the cluster is available. Smithy: PauseCluster errors = ClusterNotFoundFault (`ClusterNotFound`, 404), InvalidClusterStateFault (`InvalidClusterState`, 400), UnsupportedOperationFault. Emulator: `NotImplemented`. Why: pause-if-running automation cannot distinguish "too early, retry" from "the call is broken", and a destructively permissive emulator that later accepts the pause would also hide the state precondition. Fix: the PauseCluster handler plus the cluster state machine's status precondition in the redshift service state. Traces: redshift.pause-creating-cluster-fails.

Cause 3 of 7: EnableLogging does not validate that the destination bucket exists. AWS: enabling audit logging to a bucket that does not exist fails BucketNotFoundFault. Smithy: EnableLogging errors include BucketNotFoundFault (httpError 400, awsQueryError code `BucketNotFoundFault`), alongside InsufficientS3BucketPolicyFault, InvalidS3BucketNameFault, InvalidS3KeyPrefixFault, ClusterNotFoundFault, InvalidClusterStateFault. Message template: fixed text "Could not find bucket with name " followed by the BucketName taken from the request. Emulator: `NotImplemented`. Why: audit-logging setup code cannot tell a typo'd bucket from a missing bucket policy from a broken API, and the transition refusal -> success after creating the bucket can never be observed. Fix: the EnableLogging handler and its bucket resolution against the S3 service state. Traces: redshift.enable-logging-bucket-and-policy-errors.

Cause 4 of 7: ModifyAquaConfiguration is not stood up. AWS: the operation is retired; recorded behavior only — for a nonexistent ClusterIdentifier the recorded response is error code `InternalFailure` with the fixed message "An internal error has occurred. Please try your query again at a later time." (Smithy models ClusterNotFoundFault/InvalidClusterStateFault/UnsupportedOperationFault for ModifyAquaConfiguration and does not document the InternalFailure, so the status and code are taken from the recording.) Emulator: `NotImplemented`. Why: clients still calling the retired AQUA path get an unmodelled code; an emulator that instead made it a silent 200 no-op would be overly permissive. Fix: the ModifyAquaConfiguration handler in the redshift ops directory. Traces: redshift.modify-aqua-configuration-unsupported-rejected.

Cause 5 of 7: ModifyLakehouseConfiguration is not stood up. AWS: a nonexistent cluster fails ClusterNotFoundFault with this operation's own wording, whose fixed text is "The specified cluster identifier can't be found." (no variable parts — note it differs from DescribeClusters' "Cluster <id> not found."), and a registered cluster referencing an unknown IdC application fails RedshiftIdcApplicationNotExists. Smithy: ModifyLakehouseConfiguration errors = ClusterNotFoundFault (`ClusterNotFound`, 404), DependentServiceAccessDeniedFault (403), DependentServiceUnavailableFault, InvalidClusterStateFault, RedshiftIdcApplicationNotExistsFault (`RedshiftIdcApplicationNotExists`, 404), UnauthorizedOperation, UnsupportedOperationFault. Emulator: `NotImplemented`. Why: the two dependency-resolution faults a lakehouse client must distinguish collapse into one unmodelled code, and no registration path works at all. Fix: the ModifyLakehouseConfiguration handler, its cluster lookup and its lakehouse-registration state. Traces: redshift.modify-lakehouse-configuration-dependent-service-errors.

Cause 6 of 7: the scheduled-action operation family is not stood up. AWS: for an unknown ScheduledActionName, DescribeScheduledActions, ModifyScheduledAction and DeleteScheduledAction all fail `ScheduledActionNotFound`; CreateScheduledAction validates the schedule expression before anything else and rejects a non-cron/rate expression with InvalidParameterValue. Smithy: ScheduledActionNotFoundFault carries awsQueryError code `ScheduledActionNotFound`, httpError 400, and is listed on DescribeScheduledActions/ModifyScheduledAction/DeleteScheduledAction; CreateScheduledAction additionally models InvalidScheduleFault (`InvalidSchedule`), InvalidScheduledActionFault, ScheduledActionAlreadyExistsFault, ScheduledActionQuotaExceededFault. Emulator: all four answer `NotImplemented`. Why: nothing can schedule, list, modify or delete a scheduled pause/resize, and a caller cannot distinguish "no such action" from "unsupported". Fix: the four scheduled-action handlers plus a scheduled-action registry (and schedule-expression validation) in the redshift service state. Traces: redshift.scheduled-action-ops-semantics.

Cause 7 of 7: GetIdentityCenterAuthToken is not stood up, so its unconditional credential-type gate is unreachable. AWS: the operation is exclusive to IAM Identity Center enhanced credentials and the gate is checked BEFORE any ClusterIds validation — an ordinary IAM principal gets UnsupportedOperation, HTTP 400, with the fixed message "Request rejected: Not an IDC user acting" for a malformed cluster id, a well-formed nonexistent one and a real existing cluster alike. Smithy: GetIdentityCenterAuthToken errors = ClusterNotFoundFault, InvalidClusterStateFault, RedshiftInvalidParameterFault (`RedshiftInvalidParameter`), UnsupportedOperationFault (`UnsupportedOperation`, 400). Emulator: `NotImplemented` for all three legs. Why: a client cannot tell "your credential type is wrong" from "this cluster does not exist" from "the API is broken", and the validation precedence AWS guarantees is unobservable. Fix: the GetIdentityCenterAuthToken handler in services/service-com-amazonaws-redshift-redshiftserviceversion20121201/src/ops/get_identity_center_auth_token.rs — gate on the caller's credential type first, then validate ClusterIds. Note: a scaffold-stub issue naming this same operation and file was auto-filed for the sibling check redshift.get-identity-center-auth-token-issuance; this cause names the refusal contract (code, status and message, and its precedence over ClusterIds validation) the stood-up handler must satisfy. Traces: redshift.get-identity-center-auth-token-parameter-errors.
