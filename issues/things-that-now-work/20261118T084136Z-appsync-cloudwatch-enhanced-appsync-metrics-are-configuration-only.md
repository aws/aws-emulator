# appsync__cloudwatch: enhanced AppSync metrics are configuration-only — no AWS/AppSync series is ever published under the Resolver / DataSource / Operation dimension, so the per-resolver opt-in matrix hangs

> _Note: this issue was identified against the code base at commit `2df097800b0c216193242f0d96e30b626307c58f`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateGraphqlApi

## Description
One net-new root cause behind 1 failing behavioral check under the appsync__cloudwatch heading.

Note on an existing open issue: 20261114T022837Z-appsync-cloudwatch-appsync-graphql-errors-omit-errortype-and.md lists this same check id, but its replay key for it is bound to `run#25|AssertionError|assert _failed(warm_fail)` — the missing `errorType` member on a util.error() GraphQL error. In this replay the check gets PAST that assertion (the warm-up failing Query.c call now returns exactly one error of type `Sim2RealInjected` with a null field), so that key no longer matches and the suite reported this check as owned by nothing. The check now dies one stage later, on the enhanced-metric read, which is a different failure point from the one that issue's key gates. (That issue's Cause 3 describes the same emission gap for a DIFFERENT check id, appsync-enhanced-metrics-publish-under-api-id-resolver-dimensions, so a fixer closing it on that key alone would leave this check failing.)

Cause 1 of 1: enhancedMetricsConfig and per-resource metricsConfig round-trip as stored state, but AppSync emits no enhanced CloudWatch series at all.

AWS: Smithy com.amazonaws.appsync#EnhancedMetricsConfig has three required members — resolverLevelMetricsBehavior (enum FULL_REQUEST_RESOLVER_METRICS | PER_RESOLVER_METRICS), dataSourceLevelMetricsBehavior (enum FULL_REQUEST_DATA_SOURCE_METRICS | PER_DATA_SOURCE_METRICS) and operationLevelMetricsConfig (enum ENABLED | DISABLED). Its documentation states that enhanced metrics "emit granular data on API usage and performance such as AppSync request and error counts, latency, and cache hits/misses", that "all enhanced metric data is sent to your CloudWatch account", that resolver metrics (GraphQL errors, Requests, Latency, cache hits/misses) "will be recorded by API ID and resolver name", data-source metrics (Requests, Latency, Errors) "by API ID and data source name", and operation metrics (Requests, GraphQL errors) "by API ID and operation name"; PER_RESOLVER_METRICS / PER_DATA_SOURCE_METRICS record "metric data for resolvers/data sources that have the metricsConfig value set to ENABLED", while FULL_REQUEST_* records it for all of them in the request. Wire-level dimension spelling and the storage Unit are not in the model — recorded behavior only, as the check asserts: the series live in CloudWatch namespace AWS/AppSync, reuse the transport metric names (Requests, Latency, GraphQLError), and carry exactly one key beside GraphQLAPIId=<apiId> — Resolver="<typeName>.<fieldName>", DataSource="<data source name>" or Operation="<root operation type>"; the datapoints are stored with Unit "None" (a GetMetricStatistics with Unit="Count" must therefore return no datapoints at all), bucketed at Period=60, with Sum equal to the number of invocations driven in that bucket. These are counts derived from the traffic sent, never a value from one recording.

Emulator: the configuration is accepted and echoed faithfully (CreateGraphqlApi returns the enhancedMetricsConfig verbatim, CreateDataSource/CreateResolver return metricsConfig ENABLED/DISABLED as given), but no enhanced datapoint and no enhanced catalogue entry is ever produced. After driving successful requests through an opted-in resolver (Query.a, metricsConfig=ENABLED, on an ENABLED NONE data source), cloudwatch GetMetricStatistics(Namespace="AWS/AppSync", MetricName="Requests", Dimensions=[{GraphQLAPIId:<apiId>},{Resolver:"Query.a"}], Period=60, Statistics=["Sum"]) returns an empty Datapoints list for the whole window, and cloudwatch ListMetrics(Namespace="AWS/AppSync", Dimensions=[{GraphQLAPIId:<apiId>}]) catalogues nothing carrying a Resolver / DataSource / Operation key. The check's bounded metric poll therefore never settles and the run is killed: "Error: Check timed out after 600.0s". Because the emulator publishes nothing at all, the opted-out half of the matrix (Query.b with metricsConfig=DISABLED, the DISABLED data source, operationLevelMetricsConfig=DISABLED) and the FULL_REQUEST_RESOLVER_METRICS override that is supposed to make Query.b's series appear afterwards are never even reached — they are vacuously "absent" rather than correctly suppressed.

Why: a client that turns enhanced metrics on (and is billed for them) observes nothing. There is no per-resolver Requests/Latency/GraphQLError series, no per-data-source series and no per-operation series, so resolver-level alarming, per-resolver latency dashboards and metric-math over these series are permanently silent; worse, the opt-in semantics are unverifiable — a client cannot distinguish "this resolver is opted out" from "AppSync publishes nothing", and switching resolverLevelMetricsBehavior to FULL_REQUEST_RESOLVER_METRICS produces no observable change.

Fix: enhanced-metric emission in the AppSync resolver/data-source execution path of the appsync service (services/service-com-amazonaws-appsync-awsdeepdishcontrolplaneservice), which must honour resolverLevelMetricsBehavior / dataSourceLevelMetricsBehavior / operationLevelMetricsConfig together with each resolver's and data source's metricsConfig opt-in, and write Requests / Latency / GraphQLError into the cloudwatch metric store (services/service-com-amazonaws-cloudwatch-graniteserviceversion20100801) with the Resolver / DataSource / Operation dimension alongside GraphQLAPIId, stored with Unit "None", so that both GetMetricStatistics and ListMetrics see them.

Traces: appsync__cloudwatch.obs-appsync-1-resolver-datasource-metrics-opt-in-matrix (Error: Check timed out after 600.0s).

## Evidence
Check: appsync__cloudwatch.obs-appsync-1-resolver-datasource-metrics-opt-in-matrix — verdict mismatch, "Error: Check timed out after 600.0s".

The check reached the metric stage: CreateGraphqlApi stored enhancedMetricsConfig {resolverLevelMetricsBehavior: PER_RESOLVER_METRICS, dataSourceLevelMetricsBehavior: PER_DATA_SOURCE_METRICS, operationLevelMetricsConfig: DISABLED} verbatim, StartSchemaCreation reached SUCCESS/ACTIVE, CreateDataSource stored metricsConfig ENABLED on one NONE source and DISABLED on the other, CreateResolver stored metricsConfig ENABLED on Query.a / DISABLED on Query.b / ENABLED on Query.c, the api key worked, and all warm-up requests answered HTTP 200 with the marker — including the failing Query.c call, which returned exactly one error of errorType Sim2RealInjected with data.c null (the assertion that previously failed here now passes).

Expected after 3 successful Query.a requests inside one aligned 60 s bucket:
  - GetMetricStatistics(Namespace='AWS/AppSync', MetricName='Requests', Dimensions=[{'Name':'GraphQLAPIId','Value':<apiId>},{'Name':'Resolver','Value':'Query.a'}], StartTime=<bucket start>, Period=60, Statistics=['Sum']) -> datapoints whose Sum totals exactly the number of measured requests, each with Unit 'None';
  - the same read with Unit='Count' -> no datapoints;
  - GetMetricStatistics for MetricName='GraphQLError' under [{GraphQLAPIId:<apiId>},{Resolver:'Query.c'}] -> Sum equal to the number of util.error calls, Unit 'None';
  - ListMetrics(Namespace='AWS/AppSync', Dimensions=[{GraphQLAPIId:<apiId>}]) -> an entry ('Requests', {GraphQLAPIId:<apiId>, Resolver:'Query.a'}) and an entry ('Requests', {GraphQLAPIId:<apiId>, DataSource:<enabled ds name>}), and NO entry carrying Resolver='Query.b', DataSource=<disabled ds name> or an Operation key;
  - after UpdateGraphqlApi switches resolverLevelMetricsBehavior to FULL_REQUEST_RESOLVER_METRICS, Requests under [{GraphQLAPIId:<apiId>},{Resolver:'Query.b'}] becomes non-empty with Unit 'None', while the still-DISABLED data source and the Operation dimension stay absent.

Actual: every enhanced-dimension GetMetricStatistics read returns Datapoints == [] for the entire window and ListMetrics for the api catalogues no Resolver/DataSource/Operation entry, so the first bounded poll ("Requests under {'GraphQLAPIId': <apiId>, 'Resolver': 'Query.a'} to accumulate 3 measured requests") never satisfies its predicate and the run is terminated at the 600 s cap. No HTTP status or error code diverges — the control plane answers 200 throughout; the divergence is the complete absence of the emitted series.

## Steps to Reproduce
1. appsync CreateGraphqlApi(name=<n>, authenticationType='API_KEY', enhancedMetricsConfig={'resolverLevelMetricsBehavior':'PER_RESOLVER_METRICS','dataSourceLevelMetricsBehavior':'PER_DATA_SOURCE_METRICS','operationLevelMetricsConfig':'DISABLED'}); note apiId and uris.GRAPHQL.
2. StartSchemaCreation with `schema { query: Query } type Query { a(m: String!): String  b(m: String!): String  c(m: String!, fail: Boolean!): String }` and poll GetSchemaCreationStatus to SUCCESS/ACTIVE.
3. CreateDataSource(type='NONE', metricsConfig='ENABLED') as <dsOn> and CreateDataSource(type='NONE', metricsConfig='DISABLED') as <dsOff>.
4. CreateResolver for Query.a (kind=UNIT, dataSourceName=<dsOn>, runtime APPSYNC_JS 1.0.0, metricsConfig='ENABLED'), Query.b (dataSourceName=<dsOff>, metricsConfig='DISABLED') and Query.c (dataSourceName=<dsOn>, metricsConfig='ENABLED', request code calling util.error('<msg>','<type>') when ctx.args.fail).
5. CreateApiKey; warm up each field with a POST to uris.GRAPHQL carrying header x-api-key: <key> until each answers 200 with the echoed marker.
6. Wait for a fresh wall-clock minute boundary, then within that bucket send 3 successful Query.a requests, 3 successful Query.b requests, 2 failing and 1 succeeding Query.c requests.
7. cloudwatch GetMetricStatistics(Namespace='AWS/AppSync', MetricName='Requests', Dimensions=[{'Name':'GraphQLAPIId','Value':<apiId>},{'Name':'Resolver','Value':'Query.a'}], StartTime=<bucket start>, EndTime=now+2m, Period=60, Statistics=['Sum']) -> Datapoints is empty, and stays empty however long it is polled. AWS returns Sum=3 with Unit 'None'.
8. cloudwatch ListMetrics(Namespace='AWS/AppSync', Dimensions=[{'Name':'GraphQLAPIId','Value':<apiId>}]) -> no entry carries a Resolver, DataSource or Operation dimension. AWS catalogues ('Requests', {GraphQLAPIId, Resolver:'Query.a'}) and ('Requests', {GraphQLAPIId, DataSource:<dsOn>}) and nothing for the opted-out resolver/data source or for Operation.
9. GetMetricStatistics for MetricName='GraphQLError' under [{GraphQLAPIId:<apiId>},{Resolver:'Query.c'}] -> empty; AWS returns Sum equal to the number of util.error calls, Unit 'None'.
10. UpdateGraphqlApi(apiId=<apiId>, name=<n>, authenticationType='API_KEY', enhancedMetricsConfig={...,'resolverLevelMetricsBehavior':'FULL_REQUEST_RESOLVER_METRICS'}), drive Query.b again, and read Requests under [{GraphQLAPIId:<apiId>},{Resolver:'Query.b'}] -> still empty; AWS now publishes it (Unit 'None') while <dsOff> and the Operation dimension remain absent.
