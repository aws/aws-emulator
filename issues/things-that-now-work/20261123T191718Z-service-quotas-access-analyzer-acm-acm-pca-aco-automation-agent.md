Shared fault: the emulator's ListAWSDefaultServiceQuotas default-quota catalog is not AWS's published default-quota catalog. For nine ServiceCodes it answers HTTP 200 with a catalog that (a) omits whole published ServiceQuota rows, (b) serves rows with no Description, or (c) binds a QuotaCode to a DIFFERENT quota's name/description/value/period/usage metric. Every cause below is one ServiceCode's reply to a single ListAWSDefaultServiceQuotas call for that ServiceCode; status is 200 in both the recording and the emulator, so the divergence is purely the body.

General AWS grounding (applies to all nine causes). Smithy: ListAWSDefaultServiceQuotas(ServiceCode required, pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$) -> ListAWSDefaultServiceQuotasResponse{Quotas: ServiceQuotaListDefinition, NextToken}; ServiceQuota members ServiceCode, ServiceName, QuotaArn, QuotaCode, QuotaName, Value (QuotaValue, range 0..10000000000), Unit, Adjustable (boolean, default false), GlobalQuota, UsageMetric (MetricInfo), Period (QuotaPeriod), QuotaContext, Description (QuotaDescription, length 0..350). The MODEL fixes the shape but not the catalog's contents, so the per-quota values themselves are recorded behavior only: AWS returns, for a given ServiceCode, its complete published set of default quotas, each QuotaCode carrying ITS OWN QuotaName, Description, Value, Unit, Adjustable, Period and UsageMetric. The requirement is the pairing (QuotaCode -> that quota's metadata) and the completeness of the set, not any single recorded number.
