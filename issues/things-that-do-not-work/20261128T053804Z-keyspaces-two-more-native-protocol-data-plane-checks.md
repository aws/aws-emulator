# keyspaces: two more native-protocol data-plane checks (clustering-order slice, query on an absent table) cannot run — nothing answers on the published cassandra.<region>.amazonaws.com:9142 CQL endpoint, so the driver exhausts its reconnect budget and the checks time out

> _Note: this issue was identified against the code base at commit `cb20f68e94bbc6cb070c362820a8401b3373aae4`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
Query

## Description
One net-new root cause (Cause 1 of 1), grounded in two failing checks that both exceed their whole wall-clock budget inside the Cassandra driver's reconnect loop against the CQL endpoint the emulator publishes but does not answer on. NOTE: the open issue 20261029T194003Z-keyspaces-serves-no-cassandra-native-protocol-cql-data.md describes the same absent listener, but it carries only the replay keys for keyspaces.native-cql-round-trip, keyspaces.native-cql-lwt-concurrency and keyspaces.native-cql-unsupported-consistency-level-rejected, so neither check below is covered by it; the two further checks it does not cover are tracked in 20261109T202859Z-keyspaces-two-more-data-plane-checks-binary-protocol.md. This issue adds the two remaining checks (the ones that drive a real `cassandra` Python driver rather than a hand-rolled socket) so a fixer re-replays them too.

Cause 1 of 1 — no Cassandra native binary protocol listener on the published CQL port.
Failing check ids: keyspaces.native-cql-clustering-slice-returns-only-its-partition-rows, keyspaces.native-cql-query-on-absent-table-rejected.

AWS: the keyspaces Smithy model (com.amazonaws.keyspaces#KeyspacesService) binds a control plane only — 19 operations: CreateKeyspace, CreateTable, CreateType, Delete*/Get*/List*, RestoreTable, Tag/Untag, Update*. There is deliberately NO modeled AWS-JSON operation that writes or reads a row, so for the data plane this is recorded behavior only: Amazon Keyspaces serves rows over the Apache Cassandra native binary protocol on TLS port 9142 at cassandra.<region>.amazonaws.com. What the recordings show that endpoint doing: it accepts the TLS connection, negotiates protocol v4 (OPTIONS -> SUPPORTED with CQL_VERSION 3.4.4), demands org.apache.cassandra.auth.PasswordAuthenticator on STARTUP, completes SASL PLAIN against an IAM service-specific credential issued for ServiceName cassandra.amazonaws.com, and then serves QUERY/PREPARE/EXECUTE against the keyspaces and tables the control plane created. Two behaviors the checks here grade on top of that: (a) a clustering-range slice of one partition (WHERE pk = 'hot' AND seq > 2 AND seq <= 5) returns only that partition's rows, in the table's declared clustering order, reversed when ORDER BY <ck> DESC is given, and a full scan returns exactly the rows written (docs: https://docs.aws.amazon.com/keyspaces/latest/devguide/ordering-results.html); (b) a SELECT or INSERT naming a table the keyspace does not have is refused with an ERROR frame of protocol code 0x2200 (Invalid query) whose message is `unconfigured table <keyspace>.<table>` — fixed text `unconfigured table ` followed by the keyspace and table names taken verbatim from the statement — and the refused INSERT writes nothing, while the sibling table that does exist keeps answering; after CreateTable for that name, the identical SELECT is served and returns zero rows.

Emulator: the endpoint is published and resolves (the harness hands the checks the mapped host/port for cassandra.<region>.amazonaws.com:9142), but nothing is listening there. All control-plane work in both checks succeeds first — IAM CreateUser, PutUserPolicy, CreateServiceSpecificCredential(ServiceName=cassandra.amazonaws.com), CreateKeyspace, CreateTable, and GetTable reaching ACTIVE — and then the data-plane socket is absent. Because these two checks open the session with the real `cassandra` driver (cassandra.cluster.Cluster.connect, protocol_version=4), every attempt raises NoHostAvailable and the check's retry loop backs off (sleep min(2*2**n, 30) over up to 10 attempts), so instead of a single refusal the whole check is killed by the harness: `Check timed out after 60.0s`. The sibling checks that connect with a hand-rolled socket show the underlying error directly: `ConnectionRefusedError: [Errno 111] Connection refused` on 9142.

Why: a client gets an emulated Keyspaces where no row can ever be written or read, so none of the row-level semantics above are observable: clustering order and partition isolation, ORDER BY reversal, full-scan contents, and the 0x2200 `unconfigured table <keyspace>.<table>` refusal with its no-write guarantee. Worse, with a real driver the failure mode is not a clean refusal but a hang-then-timeout, which a user debugging their own application reads as a slow or flaky service rather than an endpoint that was never served. An emulator that announces a reachable CQL endpoint and then does not answer on it is diverging itself, not failing in the runner's environment.

Fix: the keyspaces data-plane listener — a TLS server bound to the published CQL port speaking Cassandra native binary protocol v4 (9-byte framing; OPTIONS/SUPPORTED, STARTUP/AUTHENTICATE, AUTH_RESPONSE/AUTH_SUCCESS SASL PLAIN against IAM service-specific credentials, QUERY/PREPARE/EXECUTE/RESULT, ERROR) reading and writing the SAME keyspace/table/type state the keyspaces control-plane crate already owns. Clustering-key ordering, ORDER BY handling and partition-restricted reads belong in that listener's query executor; the unconfigured-table refusal belongs in its statement resolution, which must reject before any mutation is applied. Until the listener exists and is bound to the published endpoint, neither check can get past connect and the row-level questions they ask cannot be graded.

Traces: keyspaces.native-cql-clustering-slice-returns-only-its-partition-rows (times out in _open_session's 10-attempt Cluster.connect loop), keyspaces.native-cql-query-on-absent-table-rejected (times out in the identical _session loop).

## Evidence
keyspaces.native-cql-clustering-slice-returns-only-its-partition-rows
  Verdict: mismatch — "Check timed out after 60.0s"
  The check creates the keyspace and table (partitionKeys=[sensor], clusteringKeys=[{seq, ASC}]), waits for ACTIVE, then calls _open_session(), which loops up to 10 times over cassandra.cluster.Cluster([host], port=port, ssl_context=..., protocol_version=4).connect(), swallowing NoHostAvailable and sleeping min(2*2**n, 30)s. No attempt ever connects, so the harness budget expires before the first assertion runs.
  Expected (per the recordings): the TLS connect is accepted on the published 9142 endpoint; after PasswordAuthenticator SASL PLAIN with the cassandra.amazonaws.com service-specific credential, `SELECT seq, reading FROM <ks>.readings WHERE sensor='hot' AND seq > 2 AND seq <= 5` returns [(3,'c'),(4,'d'),(5,'e')] in ascending clustering order, the same statement with `ORDER BY seq DESC` returns that list reversed, `WHERE sensor='cold'` returns only the 'cold' partition's rows, and a full scan returns exactly the 8 written rows.
  Actual: zero CQL frames exchanged; the check never reaches a CQL statement.

keyspaces.native-cql-query-on-absent-table-rejected
  Verdict: mismatch — "Check timed out after 60.0s"
  Same shape: control plane succeeds, then _session() exhausts the same 10-attempt NoHostAvailable backoff loop against the published 9142 endpoint.
  Expected (per the recordings): `SELECT id, note FROM <ks>.later_tbl` and `INSERT INTO <ks>.later_tbl (id, note) VALUES ('k2','lost')` are each refused with an ERROR frame carrying protocol code 0x2200 and message `unconfigured table <ks>.later_tbl` — the driver renders it as `Error from server: code=2200 [Invalid query] message="unconfigured table <ks>.later_tbl"`. Fixed text: `unconfigured table `; variable parts: the keyspace name and table name copied from the statement. The refused INSERT must leave the table empty once it is created, and the sibling table present_tbl must still return its single row ('k1','kept').
  Actual: zero CQL frames exchanged; neither refusal nor positive control is observable.

Corroboration that the listener, not the runner, is the cause: the sibling checks in this same service that connect with a plain socket instead of the driver fail immediately with `ConnectionRefusedError: [Errno 111] Connection refused` against the mapped cassandra.<region>.amazonaws.com:9142 address (see 20261029T194003Z-keyspaces-serves-no-cassandra-native-protocol-cql-data.md). The host:port pair in this environment is a mapping and is not itself the requirement — the requirement is that the CQL endpoint the emulator publishes answers.

## Steps to Reproduce
1. Control plane: CreateKeyspace(K); poll GetKeyspace until it answers. CreateTable(K, "readings", allColumns=[sensor text, seq int, reading text], partitionKeys=[sensor], clusteringKeys=[{seq, ASC}]); poll GetTable until status == ACTIVE.
2. IAM: CreateUser(U); PutUserPolicy allowing cassandra:Select and cassandra:Modify on arn:aws:cassandra:<region>:<account>:/keyspace/K/ and .../table/*; CreateServiceSpecificCredential(UserName=U, ServiceName="cassandra.amazonaws.com") and keep ServiceUserName/ServicePassword.
3. With the Python `cassandra` driver, resolve the endpoint the emulator publishes for cassandra.<region>.amazonaws.com port 9142 and call Cluster([host], port=port, ssl_context=<TLS, verify off>, auth_provider=PlainTextAuthProvider(ServiceUserName, ServicePassword), protocol_version=4).connect().
4. Observe: every connect raises NoHostAvailable (nothing is listening); with the driver's reconnect backoff the caller simply hangs and the check is killed at its 60 s budget. A plain socket to the same address gets ECONNREFUSED.
5. Expected instead: the connect succeeds, STARTUP -> AUTHENTICATE org.apache.cassandra.auth.PasswordAuthenticator -> AUTH_SUCCESS; then (a) INSERT the rows (hot,4,d),(hot,1,a),(hot,6,f),(hot,3,c),(hot,5,e),(hot,2,b),(cold,3,x),(cold,9,y) and verify the slice/ORDER BY DESC/partition-isolation/full-scan results above; and (b) against a keyspace holding only present_tbl, verify that SELECT and INSERT naming later_tbl are refused with 0x2200 `unconfigured table <K>.later_tbl`, that GetTable(K, later_tbl) answers ResourceNotFoundException `unconfigured table later_tbl`, and that after CreateTable(K, later_tbl) the identical SELECT returns zero rows.
