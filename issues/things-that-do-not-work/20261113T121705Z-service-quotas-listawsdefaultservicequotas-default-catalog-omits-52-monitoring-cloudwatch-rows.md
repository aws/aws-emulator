# ListAWSDefaultServiceQuotas default catalog omits 52 monitoring (CloudWatch) rows and understates two API-rate quota Values

## Description

Looking up any of those 52 quota codes finds nothing, so the client reports the quota as nonexistent or skips it instead of seeing the AWS default; and for the two codes it does find, it plans against half the real default, so a limit check that should pass fails (or a request-increase flow asks for a value AWS already grants by default).

Fix: the default-quota catalog data consulted by ListAWSDefaultServiceQuotas in the service-quotas crate — the monitoring/Amazon CloudWatch entries are almost entirely unseeded and two rate rows hold a wrong default Value. Belongs in the catalog seed/state behind the operation's handler (services/service-com-amazonaws-servicequotas-servicequotasv20190624/src/ops + src/state.rs), not in the serializer: the response shape itself is well-formed. The same catalog feeds ListServiceQuotas, GetAWSDefaultServiceQuota and GetServiceQuota, so those reads for monitoring are wrong in the same way.
