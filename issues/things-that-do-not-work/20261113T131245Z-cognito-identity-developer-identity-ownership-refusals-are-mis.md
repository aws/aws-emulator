# cognito-identity: developer-identity ownership refusals are mis-classified or missing

> _Note: this issue was identified against the code base at commit `e893cd19d3c9bb8dc2178e48ce28ce64f933efef`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
GetOpenIdTokenForDeveloperIdentity

## Description
This issue bundles 2 net-new root causes on the developer-authenticated identity path. In both, the emulator fails to decide correctly that the caller does NOT own the identity it names: once it re-labels that refusal as an identity-merge conflict, and once it does not refuse at all. Protocol is awsJson1_1, so the error class is carried both in the body member `__type` and in the `x-amzn-errortype` response header, and a wrong (or absent) class is wrong in both places.

Cause 1 of 2: GetOpenIdTokenForDeveloperIdentity called with an explicit IdentityId together with a developer-provider login that is registered to a DIFFERENT identity in the same pool. AWS: the supplied Logins do not prove ownership of the named identity, so this is an authorization refusal, not a merge — HTTP 400 with `__type` NotAuthorizedException, header `x-amzn-errortype: NotAuthorizedException:`, and the message "Logins don't match. Please include at least one valid login for this identity or identity pool." That message is entirely fixed text: it has no variable parts drawn from the request or from state. Smithy (com.amazonaws.cognitoidentity#AWSCognitoIdentityService, awsJson1_1): GetOpenIdTokenForDeveloperIdentity errors = DeveloperUserAlreadyRegisteredException(400), InvalidParameterException(400), NotAuthorizedException(@httpError 403), ResourceConflictException(@httpError 409), ResourceNotFoundException(404), TooManyRequestsException(429), InternalErrorException(500); input IdentityId is an IdentityId (@length 1..55, pattern ^[\w-]+:[0-9a-f-]+$) and Logins is a required LoginsMap (@length 0..10). The model does not state which error covers a login/identity ownership mismatch, and the recorded AWS status is 400 rather than the modeled 403 — that part is recorded behavior only. Emulator: HTTP 400 but `__type` ResourceConflictException, header `x-amzn-errortype: ResourceConflictException:`, message 'Cannot merge these identities.' It treats a login that belongs to another identity as a request to merge the two identities instead of as a failure to prove ownership of the one named. Why: a client branches on these two classes differently — NotAuthorizedException means 'send a valid login for this identity' (re-authenticate / correct the IdentityId), while ResourceConflictException means 'these two identities exist and cannot be combined', which suggests an unlinking workflow that cannot help here. The emulator's message also offers a remedy that does not apply, so negative tests written against AWS fail only on the emulator. Note this is the INVERSE direction of cause 2 of the open issue '20261030T212445Z-cognito-identity-developer-identity-token-and-credential-refusals.md' (which reports a genuine cross-identity merge conflict answered as NotAuthorizedException at cogid-merge-idp-proven-identity-login-conflicts#task#12); that issue does not carry this fixture/step and does not cover this case, so the two selections must be told apart rather than swapped. Fix: the error selection in the GetOpenIdTokenForDeveloperIdentity handler — decide ownership of the supplied IdentityId from the supplied Logins first and raise NotAuthorizedException with AWS's fixed message; reserve ResourceConflictException for the case where the logins each prove a different existing identity. Traces: cogid-merge-developer-login-of-other-identity-refused#task#5.

Cause 2 of 2: LookupDeveloperIdentity called with an IdentityId the calling context is not entitled to inspect (an identity in the pool that the request's proven logins do not own). AWS: HTTP 400 with `__type` NotAuthorizedException, header `x-amzn-errortype: NotAuthorizedException:`, and the message 'You do not have access to this identity' — entirely fixed text, no variable parts. Smithy: LookupDeveloperIdentity errors = InvalidParameterException(400), NotAuthorizedException(@httpError 403), ResourceConflictException(409), ResourceNotFoundException(404), TooManyRequestsException(429), InternalErrorException(500); input IdentityPoolId required, IdentityId and DeveloperUserIdentifier optional. The model does not express the ownership check and the recorded status is 400, not the modeled 403 — recorded behavior only. Emulator: HTTP 200 with a normal LookupDeveloperIdentity response body (no `__type`, no `message`, no `x-amzn-errortype` header), i.e. it answers the lookup for an identity the caller may not read. Why: this is the more severe cause — the emulator discloses the developer-user identifiers linked to an identity the caller has no access to and tells the caller it succeeded. Any authorization test asserting that cross-identity lookups are refused passes against AWS and fails only here, and application logic that uses a successful lookup as proof of ownership draws the wrong conclusion. Fix: the authorization/ownership check in the LookupDeveloperIdentity handler (before the identity's developer-user list is read from state), raising NotAuthorizedException with AWS's fixed message. Traces: cogid-merge-idp-proven-identity-login-conflicts#task#14.
