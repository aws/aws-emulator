# ds: 2 net-new causes — the CA-enrollment toggle refusals are emulator-authored instead of AWS's text (DisableCAEnrollmentPolicy no-policy, EnableCAEnrollmentPolicy unknown PCA connector)

> _Note: this issue was identified against the code base at commit `f2ca0d33a4ef403d011f2f8fe60e4cf271401df3`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
DisableCAEnrollmentPolicy

## Description
Two net-new behavioral root causes in the Directory Service (ds) CA-enrollment control plane. In both the emulator picks the RIGHT modeled error class (EntityDoesNotExistException) and the right HTTP 400, but words the message itself instead of reproducing AWS's text. An error message is a requirement, not decoration: these are two distinct message templates owned by two distinct refusal sites, and a fixer must close BOTH before submitting.

Cause 1 of 2 — DisableCAEnrollmentPolicy on a directory that holds no CA enrollment policy answers the generic exception sentence instead of AWS's no-CA-enrollment-info text.
AWS: Smithy (services/service-com-amazonaws-directoryservice-directoryservice-20150416/smithy-model/com-amazonaws-directoryservice-directoryservice-20150416.json): DisableCAEnrollmentPolicy takes only DirectoryId (@required, @pattern ^d-[0-9a-f]{10}$) and models EntityDoesNotExistException (client, HTTP 400, documented "The specified entity could not be found."). Recorded behavior: on an ACTIVE Managed Microsoft AD whose policy was never successfully enabled, the call is refused synchronously with code EntityDoesNotExistException and this message template — fixed text: "No CA enrollment info found for directory " <directory id> " with Inner Exception: NoResultFoundException: No CA enrollment info found for directory " <directory id>, then the service envelope " : RequestId: " <request id>; variable parts: the directory id, which appears TWICE and is taken verbatim from the request, and the envelope's per-call request id. The inner-exception clause naming NoResultFoundException and the repetition of the directory id are fixed text — AWS surfaces its downstream lookup failure here, it does not collapse the refusal to the shape's documentation string.
Emulator: answers the right code and 400 with the shape's doc sentence verbatim — "The specified entity could not be found. : RequestId: <rid>" — carrying neither the directory id nor the inner-exception clause.
Why: this is the only refusal that tells a caller "there is no enrollment to withdraw on THIS directory", and it is the message a client sees whenever it disables a policy it never enabled, or disables twice. A client that matches AWS's text to decide "nothing to undo, continue teardown" never matches; one that parses the directory id out of the message to attribute the failure in a multi-directory sweep finds no id at all, and the generic sentence is indistinguishable from every other EntityDoesNotExistException the service emits.
Fix: DisableCAEnrollmentPolicy's handler, the policy-absent refusal branch (services/service-com-amazonaws-directoryservice-directoryservice-20150416/src/ops/disable_ca_enrollment_policy.rs, the `policy_absent` closure at ~line 205 and its second use at ~line 226), and the constant it refuses with, `crate::state::CA_ENROLLMENT_POLICY_ABSENT` in src/state.rs — the message must be built from the request's DirectoryId rather than being a constant.
Traces: ds.ca-enrollment-disable-not-enabled-rejected, ds.ca-enrollment-policy-toggle-server-managed. (ds.server-side-ca-enrollment-policy-toggle-enforced asserts this same template too, but fails on cause 2 first.)

Cause 2 of 2 — EnableCAEnrollmentPolicy with a well-formed but nonexistent PcaConnectorArn is re-worded and drops the embedded downstream AWSPcaConnectorAd error envelope.
AWS: Smithy: EnableCAEnrollmentPolicy takes DirectoryId (@required) and PcaConnectorArn (@required, @pattern ^arn:[\w-]+:pca-connector-ad:[\w-]+:[0-9]+:connector\/[0-9a-f]{8}(-[0-9a-f]{4}){3}-[0-9a-f]{12}$) and models EntityDoesNotExistException (client, HTTP 400). Recorded behavior: DS resolves the connector in the PCA Connector AD service and relays THAT service's failure inside its own message. Template — fixed text: "Connector not found for ARN: " <pca connector arn> ". Connector was not found: " <pca connector arn> ". (Service: AWSPcaConnectorAd; Status Code: 404; Error Code: ResourceNotFoundException; Request ID: " <the inner pca-connector-ad call's request id> "; Proxy: null) : RequestId: " <this call's request id>; variable parts: the connector ARN from the request (it appears TWICE), the inner request id, and the envelope request id. The relayed "(Service: AWSPcaConnectorAd; Status Code: 404; Error Code: ResourceNotFoundException; ...; Proxy: null)" envelope, including the downstream 404 and ResourceNotFoundException code, is fixed text.
Emulator: answers the right code and 400 with an emulator-authored sentence — "PCA connector: '<arn>' does not exist. : RequestId: <rid>" — a quoted-ARN generic not-found builder, with no second ARN clause and no downstream service/status/error-code envelope at all.
Why: the embedded envelope is what tells a caller WHICH service rejected the enrollment and that the connector (not the directory, and not permissions) is the missing resource; collapsing it to a generic "does not exist" sentence erases the distinction between a connector that is absent and the directory-level EntityDoesNotExistException the same operation can raise. Clients that surface the downstream error code to an operator, or match on "Connector not found for ARN:" to prompt "create the PCA connector first", diverge on every rejected Enable, including the retry of the same bad ARN.
Fix: EnableCAEnrollmentPolicy's handler, the ConnectorDefect::Absent branch (services/service-com-amazonaws-directoryservice-directoryservice-20150416/src/ops/enable_ca_enrollment_policy.rs ~lines 248-254) and the message builder it calls, `crate::state::no_such_pca_connector` in src/state.rs — it must emit the relayed AWSPcaConnectorAd envelope rather than the service's generic quoted-entity not-found wording.
Traces: ds.ca-enrollment-policy-server-enforced-toggle, ds.server-side-ca-enrollment-policy-toggle-enforced.

Both causes are message-only: the chosen exception shape, the HTTP 400, and the state effects all match AWS — DescribeCAEnrollmentPolicy keeps reporting Disabled across both rejected calls, and the rejected connector ARN is not persisted, so those legs of the checks pass.

Related open issue that does NOT cover these (it carries none of the four check ids above): 20261102T102235Z-ds-eight-refusal-messages-are-emulator-authored-instead.md records the same CLASS of defect for ShareDirectory, certificates, conditional forwarders, trusts, DescribeDirectories and EnableLDAPS; the two CA-enrollment templates above are different refusal sites in different handlers.
