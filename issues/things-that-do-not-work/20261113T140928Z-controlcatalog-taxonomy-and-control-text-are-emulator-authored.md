# ControlCatalog taxonomy and control text are emulator-authored paraphrases over fabricated ARNs

> _Note: this issue was identified against the code base at commit `0e0bbca79734649b97ab70170a0bc1f3e6da2e9e`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListDomains

## Description
Across ListDomains, ListObjectives and ListControls the emulator answers 200 but the catalog entries it serves carry descriptions it wrote itself instead of the text AWS publishes, and - for the two taxonomy levels - part of the list is made up of entries whose ARNs appear in no published catalog while real published entries are absent. The Description member is @required on all three summary shapes, so this is wrong required content, not cosmetic drift. Three operations and two different data tables are involved; this bundle carries 4 causes.

The open issue "ControlCatalog taxonomy list operations serve none of the real domains or objectives" (20261106T092706Z-controlcatalog-taxonomy-list-operations-serve-none-of-the.md) does NOT cover causes 1 and 2: it describes the state in which NONE of the published domains/objectives is matched at all, whereas the replay now matches several of them by ARN and diverges on their Description (plus a residue of fabricated and missing elements) - a different divergence that the replay reports as unowned. The open issue "ListControls replaces AWS Config catalog controls with emulator-minted summaries (identity, aliases, parameter summary)" (20261106T180948Z) likewise does not cover causes 3 and 4, which are Description-only mismatches on controls the emulator does serve under their real ARNs. No resolved issue covers any of the four.

Cause 1 of 4: ListDomains serves paraphrased domain descriptions plus fabricated domains, and omits most published ones. AWS: Smithy (services/service-com-amazonaws-controlcatalog-controlcatalog/smithy-model/com-amazonaws-controlcatalog-controlcatalog.json) - ListDomains is POST /domains, @readonly, success 200, input {MaxResults @range 1..100, NextToken @length max 1024}, output ListDomainsResponse {Domains (DomainSummaryList) @required, NextToken}. DomainSummary requires Arn (DomainArn, @length 33..2048, @pattern ^arn:(aws(?:[-a-z]*)?):controlcatalog:::domain/[0-9a-z]+$), Name, Description, CreateTime and LastUpdateTime. The domain taxonomy is an AWS-published, account- and region-independent read-only catalog, so an unfiltered ListDomains must enumerate the published domain set, each element carrying that domain's published Name and its published Description verbatim. The recording shows the published text, e.g. for arn:aws:controlcatalog:::domain/d4msesd9vvmzmmuvlv06m92uq ("Asset management") the Description is "This control domain focuses on asset management and the systematic tracking and maintenance of physical or digital assets throughout their lifecycle, including acquisition, utilization, and disposal. This reduces risks related to accidents, malfunctions, and other issues that may cause damage to property or harm to people." Emulator: 200, and for the published domains it does serve the Description is a short self-authored sentence instead - e.g. "Controls that inventory Amazon Web Services resources and keep that inventory current." for Asset management, "Controls that keep workloads available, and restore them after a disruption." for Business continuity and recovery (.../domain/33mjpzadrlwo1by3c1012ai5i), "Controls that protect the confidentiality and integrity of data at rest and in transit." for Data protection (.../domain/884eyhr622uy73h6i1mjb9lfb) and "Controls that govern who can reach Amazon Web Services resources, ..." for Identity and access management (.../domain/avh1ncrx6oyndrbsv0rfywvat). In the same response a further set of published domains is entirely absent (.../domain/2oc9yao2szxsquya737481hw9, /70qzkmyi2s3oxheokg6jqqiy7, /996b3qixyfm57kat9vwwu8hy1, /acslzu9jr992jv4hjejegjnf0, /bn9ck1b74fp4b4wdysq0fanpc, /bqimrxnye01kph8z4lvy0ndp8, /eyrstdrz8kmo28x5j8vgal6au, /1yz9ep0ymkt1vufn0y3kyyhzv, /22ctir35fm1yojdh1sr4iucq7) while extra members are returned under ARNs of 25 hexadecimal digits that exist in no published catalog (/01d780d3ff2c8fd25185836de, /262d5c3b7a044409c5bb65351, /42a34489dabde1c06b0d71d19, /5a896e7e7ceb11a89e715befb, /91f98f5928d9d01b6182f38b2, /d2e7eca3d54970a4b9a7706f8, /d6bd44b00c948ef00c6d8ddfa, /e37fac1dcbed9ed914ae39b0d, /ea07419970edbeb8b40f29027, /fc76959dae9dbcca8c896fd77). Why: ListDomains is the entry point a client uses to discover domain ARNs for ListObjectives/ListCommonControls filters and to render a catalog tree with its published wording; against the emulator it gets wording that is not AWS's (so any UI, export or compliance document built from it is wrong) and ARNs that resolve nowhere else in the catalog, while the real domains it needs are missing. Fix: the ListDomains handler's backing ControlCatalog taxonomy state/seed data - the domain table must hold exactly the published domains keyed by their real ARNs with their published Name and Description and their create/last-update times, and the handler must page that table per MaxResults/NextToken. Traces: controlcatalog-catalog-list-domains#task#1.
