# codecommit__sns__sqs: 2 net-new causes — TestRepositoryTriggers reports success for a topic whose policy denies CodeCommit sns:Publish, and a FIFO-topic destination fails with a leaked SNS InvalidParameter instead of the unsupported-topic-type message

> _Note: this issue was identified against the code base at commit `ab3264a14a30dede061951437467343aaef14e5b`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
TestRepositoryTriggers

## Description
Two net-new root causes in CodeCommit's TestRepositoryTriggers destination handling, both grounded in failing checks the replay report left unmarked.

Cause 1 of 2: a trigger whose destination topic policy denies CodeCommit sns:Publish is reported as a successful execution.
AWS: Smithy TestRepositoryTriggers returns successfulExecutions and failedExecutions (members trigger, failureMessage); it works by actually sending information to the trigger target (https://docs.aws.amazon.com/codecommit/latest/APIReference/API_TestRepositoryTriggers.html). When the destination topic's resource policy does not permit the CodeCommit service principal to Publish, CodeCommit cannot deliver: that trigger appears in failedExecutions with the fixed failureMessage 'AWS CodeCommit does not have access to the destination, the destination's KMS key or the destination does not exist.', it is absent from successfulExecutions, and nothing is delivered to any subscriber of that topic; the control trigger on a permissive twin topic appears in successfulExecutions and its record reaches the subscribed queue.
Emulator: both the control and the denying trigger are returned in successfulExecutions with failedExecutions empty, so the topic-policy denial is never evaluated.
Why: an operator uses this call to confirm a trigger can reach its destination before depending on it; reporting a topic that will reject every publish as 'successful' validates a configuration under which no notification will ever arrive.
Fix: the destination-authorization evaluation in services/service-com-amazonaws-codecommit-codecommit-20150413/src/ops/test_repository_triggers.rs — evaluate the SNS topic policy for the CodeCommit service principal's sns:Publish before reporting success, and report the failure with AWS's fixed no-access failureMessage.
Traces: codecommit__sns__sqs.test-repository-triggers-to-a-topic-denying-publish-rejected-and-delivers-nothing.

Cause 2 of 2: a FIFO-topic destination is failed with a leaked SNS parameter error instead of CodeCommit's unsupported-topic-type message.
AWS: recorded behavior only (the model does not enumerate destination types). SNS FIFO topics are not supported as CodeCommit trigger destinations, so TestRepositoryTriggers puts that trigger in failedExecutions with the fixed failureMessage 'The SNS topic type is not valid. Amazon SNS FIFO (first in, first out) topics are not supported for CodeCommit triggers. Either choose an SNS topic that has its type set to Standard, or configure an Amazon EventBridge rule for CodeCommit events that has the SNS FIFO topic configured as its target.' — entirely fixed text naming the remedy; the standard-topic twin in the same call succeeds and delivers.
Emulator: the trigger is failed, but with the failureMessage 'Unable to send the notification to <topicArn>: InvalidParameter: Invalid parameter: The MessageGroupId parameter is required for FIFO topics' — the raw error from the attempted SNS Publish, with the topic ARN interpolated. The emulator therefore tries to publish to a destination type CodeCommit rejects up front, and surfaces SNS's parameter complaint instead of CodeCommit's own diagnosis.
Why: the failureMessage is what tells the operator that FIFO topics are categorically unsupported and what to do instead (a Standard topic, or an EventBridge rule targeting the FIFO topic). The leaked message instead suggests a missing request parameter, which no caller of TestRepositoryTriggers can supply, and it exposes an internal publish attempt as the diagnosis.
Fix: the destination-type validation in services/service-com-amazonaws-codecommit-codecommit-20150413/src/ops/test_repository_triggers.rs (and the same validation used by put_repository_triggers.rs) — classify an SNS FIFO destination before any publish is attempted and report AWS's fixed unsupported-topic-type failureMessage.
Traces: codecommit__sns__sqs.test-repository-triggers-to-a-fifo-topic-rejected-while-a-standard-twin-delivers.
