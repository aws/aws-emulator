=== Cause 1 of 8: the minted streaming-session URL announces scheme https:// while the listener that serves it speaks plain HTTP, so every media player handed the URL dies in the TLS handshake ===
AWS: Smithy com.amazonaws.kinesisvideoarchivedmedia#GetDASHStreamingSessionURL / GetHLSStreamingSessionURL (restJson1, sigv4) return DASHStreamingSessionURL / HLSStreamingSessionURL, documented as "The URL (containing the session token) that a media player can use to retrieve the MPEG-DASH manifest" / "the HLS master playlist". The operation docs say the caller must "Provide the URL (containing the encrypted session token) ... to a media player that supports the ... protocol" — the contract is OPERATIONAL: the URL, AS ANNOUNCED (scheme included), must be fetchable by an ordinary HTTP client with default TLS settings. Host, port and token are per-environment values and are not requirements; the agreement between the announced scheme and the transport the listener actually serves is. Recorded behavior only for the scheme itself.
Emulator: services/service-com-amazonaws-kinesisvideoarchivedmedia-awsacuityreader/src/state.rs:766-782 (`session_url`) composes the URL as `format!("https://{host}{}", session_resource_path(...))` — the scheme is hardcoded https while the `host` is taken from the request's own Host header, i.e. the data-plane listener the SDK client just reached over plain HTTP (the same listener answers /getDASHStreamingSessionURL fine in these very checks). A client that GETs the announced URL therefore sends a TLS ClientHello to a plaintext socket and is refused in the handshake: `urllib.error.URLError: <urlopen error [SSL: WRONG_VERSION_NUMBER] wrong version number>` and `requests.exceptions.SSLError: HTTPSConnectionPool(host='127.0.0.1', port=<port>): Max retries exceeded with url: /dash/v1/getMPDManifest.mpd?SessionToken=<token> (Caused by SSLError(SSLError(1, '[SSL: WRONG_VERSION_NUMBER] wrong version number')))`. The loopback host, port and token differ per run and are not the divergence; announcing a scheme the socket does not serve is.
Why: the session URL is the ONLY way to play an archived stream over HLS/DASH. Every player (ffplay, hls.js, dash.js, the KVS sample consumers) and every client that follows the returned URL fails at connect time with a transport error, never an AWS error, so the whole playback plane is unusable and no manifest, playlist, init fragment or media fragment can ever be fetched — even for streams whose session was minted successfully. This is the same defect family as the already-fixed 20261107T004725Z-kinesis-video-archived-media-data-plane-is-unreachable.md, but on the SESSION URL rather than on GetDataEndpoint: the data endpoint is now dialable, the URL this plane publishes for itself is not.
Fix: the session-URL composition shared by both streaming-session handlers — `session_url` in services/service-com-amazonaws-kinesisvideoarchivedmedia-awsacuityreader/src/state.rs (:766-782), which must carry the scheme the listener it names actually serves (the scheme the caller reached the emulator on) rather than a constant https.
