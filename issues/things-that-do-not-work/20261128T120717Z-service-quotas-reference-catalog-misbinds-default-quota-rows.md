# service-quotas reference catalog misbinds default-quota rows and omits ListServices entries

> _Note: this issue was identified against the code base at commit `96996ff548d771d992d512709b10ef647dc44007`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
The emulator's built-in Service Quotas reference catalog diverges from the catalog AWS publishes. Every cause below is the SAME fault in two tables: the per-ServiceCode default-quota row table that backs ListAWSDefaultServiceQuotas, and the service table that backs ListServices. In both, rows are published under the wrong key (a quota's facts appear under another quota's QuotaCode, a service's entry appears at another service's position) or are absent entirely, and some rows drop Description. Every affected step answers HTTP 200 with a well-formed body, so no client sees an error - only wrong catalog content.

THE RULE (shared by all eight causes). A row published under a QuotaCode carries the QuotaName, Value, Unit, Adjustable, GlobalQuota, Period, UsageMetric and Description of the quota AWS publishes UNDER THAT CODE, worded as the service words it and never paraphrased or borrowed from a neighbouring quota; a quota AWS publishes is published, and a quota AWS does not publish under a code is published under no code. Likewise every ServiceCode/ServiceName pair AWS lists in ListServices is listed. Smithy fixes only the SHAPE (ServiceQuota: QuotaCode @length 1..128 @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$, QuotaName, Value -> QuotaValue @range 0..10000000000, Unit, Adjustable @default false, GlobalQuota @default false, UsageMetric -> MetricInfo, Period -> QuotaPeriod, QuotaContext, Description @length 0..350; ServiceInfo: ServiceCode @length 1..63, ServiceName; ListAWSDefaultServiceQuotas input ServiceCode required, output Quotas -> ServiceQuotaListDefinition, paginated by NextToken/MaxResults; ListServices output Services -> ServiceInfoListDefinition). The per-code and per-service CONTENT is recorded behavior only, so each fixture's recorded response is the reference for it.

RELATED BUT NOT COVERING THIS. Cause 1 of 8 - ListAWSDefaultServiceQuotas, ServiceCode "events".
AWS: recorded behavior only (the model constrains the row shape, not its content). The recording publishes L-8331B29E as QuotaName "[EventsV2] Events per second per custom event bus", Value 500000.0, with the Description the service words for it; L-E2110C81 as "[EventsV2] Combined ingestion throughput and count per Event Group per second", Value 1500.0; and L-D082A4F6 with Description "The maximum number of Event Sources owned by this account per Region.".
Emulator: HTTP 200, but L-8331B29E carries "PutTargets throttle limit in transactions per second" / Value 50.0 / the PutTargets request-rate Description, L-E2110C81 carries "ListRules throttle limit in transactions per second" / Value 50.0 / the ListRules request-rate Description, and L-D082A4F6 is returned with Description absent (null).
Why: a client reading the EventBridge default quota for ingestion per bus is handed an API request-rate limit two to four orders of magnitude smaller (50 vs 500000), so capacity planning and any quota-driven admission check compute the wrong headroom, and a row with no Description renders empty in a console or report.
Fix: the service-quotas default-quota catalog data for ServiceCode "events" (the per-code row table the ListAWSDefaultServiceQuotas handler reads), re-keyed so each code carries its own recorded row and no Description is dropped.
Traces: service-quotas-catalog-list-aws-default-service-quotas-events#task#1.
