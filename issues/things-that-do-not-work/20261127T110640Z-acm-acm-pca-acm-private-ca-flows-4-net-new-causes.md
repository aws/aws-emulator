# acm (private-CA flows): 4 net-new causes — export-passphrase ValidationException prints "Value null", RenewCertificate reissues no new Serial, never-exported private cert gets the public/imported refusal text, and Options.Export is accepted for a private CA

> _Note: this issue was identified against the code base at commit `0e14ec34ba796ebb423716588b97f90ad61f6019`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
RequestCertificate

## Description
Four distinct net-new root causes in the emulator's ACM handling of private-CA (ACM Private CA issued) certificates. All four are grounded in behavioral checks that pass against real AWS, and none of them is covered by an open issue: the closest one, 20261022T143245Z-acm-certificate-representation-dns-validation-and-error-message.md (its Cause 7 covers the generic "Value of the input at '<member>'" constraint envelope), does not cover the sensitive-blob form in Cause 1, and no open issue touches RenewCertificate or RequestCertificate.Options at all.

Cause 1 of 4: the constraint-violation ValidationException for a too-short ExportCertificate passphrase injects the literal token "null" where AWS emits no value at all.
AWS: Smithy ExportCertificate.Passphrase -> PassphraseBlob, @required, blob, @sensitive, @length min 4 max 128; the operation models ValidationException (client error, HTTP 400, awsQueryError ValidationError). Recorded behavior: a passphrase shorter than 4 bytes is refused with HTTP 400, Error.Code 'ValidationException' and Error.Message "1 validation error detected: Value at 'passphrase' failed to satisfy constraint: Member must have length greater than or equal to 4". Fixed text: "1 validation error detected: Value at '", "' failed to satisfy constraint: Member must have length greater than or equal to ". Variable parts: the member name taken from the request shape ('passphrase') and the limit taken from the model (4). Because the member is @sensitive the value is NOT echoed and no placeholder stands in for it — the message reads "Value at 'passphrase'", with nothing between "Value" and "at".
Emulator: same status and code, but the message is "1 validation error detected: Value null at 'passphrase' failed to satisfy constraint: Member must have length greater than or equal to 4" — the builder renders the suppressed sensitive value as the string "null" instead of omitting that slot.
Why: the rule, not one recording's text, is the requirement. A client or test that matches ACM's validation envelope byte-for-byte (or parses it to recover the offending member) does not match, and the stray "null" reads as if the request had sent a null passphrase rather than a short one.
Fix: the shared constraint-violation message builder for this service's ValidationException — when the violated member is @sensitive (or the value is withheld), emit the "Value at '<member>'" form with no placeholder token, rather than formatting Option::None as "null".
Traces: acm__acm-pca.export-certificate-private-ca-passphrase-length-rejected.

Cause 2 of 4: RenewCertificate on an eligible private-CA certificate reports RenewalStatus SUCCESS but never reissues — the certificate keeps its old Serial.
AWS: Smithy RenewCertificate{CertificateArn} -> Unit, and CertificateDetail carries Serial plus RenewalSummary{RenewalStatus, RenewalStatusReason}; RenewalEligibility is the enum ELIGIBLE|INELIGIBLE. Recorded behavior: once a private-CA certificate has been exported it reports RenewalEligibility ELIGIBLE, and a forced RenewCertificate drives RenewalSummary.RenewalStatus to SUCCESS and replaces the certificate material — DescribeCertificate then reports a Serial DIFFERENT from the pre-renewal one, because ACM asks the private CA to issue a new certificate.
Emulator: the renewal is accepted and RenewalSummary.RenewalStatus does reach SUCCESS, but DescribeCertificate still returns the pre-renewal Serial unchanged (the check compares the post-renewal Serial against the value it captured before the call and finds them equal). The renewal is therefore a status-only state change with no reissuance.
Why: a client that renews a certificate and then detects the rotation by comparing Serial (or by reading the new NotAfter/certificate body) concludes the renewal silently did nothing, and any rotation workflow keyed on "material changed" loops forever; conversely a test suite that trusts RenewalStatus SUCCESS ships code that never actually rotates.
Fix: the RenewCertificate handler and the certificate state it mutates in the ACM service crate — on a successful forced renewal, issue fresh certificate material through the backing private CA and store the new Serial (and the new validity/body) on the certificate, instead of only writing RenewalSummary.
Traces: acm__acm-pca.private-ca-certificate-renewal-eligible-after-export.

Cause 3 of 4: RenewCertificate on a never-exported private-CA certificate is refused with the message AWS reserves for public/imported certificates.
AWS: RenewCertificate models ValidationException (client error, HTTP 400). Recorded behavior: a certificate issued by an ACTIVE private CA that has never been exported reports Type PRIVATE and RenewalEligibility INELIGIBLE, and RenewCertificate on it is refused with HTTP 400, Error.Code 'ValidationException' and Error.Message "Certificate ARN <certificateArn> has not been exported so it is not eligible for the Renew Certificate API." Fixed text: "Certificate ARN " and " has not been exported so it is not eligible for the Renew Certificate API." (terminating period included). Variable part: the certificate ARN echoed from the request. AWS distinguishes this ineligibility class (private, not yet exported) from the public/imported class, which carries the different text "... is for a public or imported certificate and not eligible for the Renew Certificate API".
Emulator: correct status and code, but the message is "Certificate ARN <certificateArn> is for a public or imported certificate and not eligible for the Renew Certificate API" — the public/imported text (and without a terminating period) for a certificate the emulator itself reports as Type PRIVATE.
Why: the two messages mean different things and imply different remedies — the AWS text tells the caller to export the certificate first, the emulator's text tells the caller the certificate can never be renewed through this API. Error-handling branches keyed on the ineligibility reason take the wrong path, and the emulator contradicts its own DescribeCertificate projection (Type PRIVATE).
Fix: the RenewCertificate handler's eligibility gate — classify the refusal by the certificate's Type and export history (private + never exported vs public/imported) and select the matching ValidationException message, including the trailing period on the not-exported form.
Traces: acm__acm-pca.private-ca-certificate-renewal-ineligible-before-export.

Cause 4 of 4: RequestCertificate accepts Options{Export: ENABLED} together with CertificateAuthorityArn and mints a PRIVATE certificate AWS refuses to create.
AWS: Smithy RequestCertificate.Options -> CertificateOptions{CertificateTransparencyLoggingPreference, Export, ValidationMethod}; CertificateOptions.Export is documented as the opt-in for exporting your certificates and applies to public certificate types, while CertificateAuthorityArn (PcaArn) selects an ACM Private CA and produces a PRIVATE certificate. Recorded behavior (RequestCertificate does not model ValidationException, so this is recorded behavior only): the combination is refused with HTTP 400, Error.Code 'ValidationException' and Error.Message "One or more of the options specified in the request are not supported for PRIVATE certificate types." — a fixed string with no variable parts — and no certificate is created (the domain never appears in ListCertificates). The identical call WITHOUT Options succeeds and yields a Type PRIVATE certificate that reaches ISSUED.
Emulator: the call SUCCEEDS with HTTP 200 and returns a CertificateArn, so an unsupported option set is accepted and a certificate is minted and listed.
Why: this is over-permissive — a template or script that sets Options.Export on a private-CA certificate passes against the emulator and is rejected in production, and the emulator's certificate then carries an option combination AWS considers impossible, so any behavior derived from Export on a PRIVATE certificate is fiction.
Fix: request validation in the RequestCertificate handler — when CertificateAuthorityArn is present (PRIVATE certificate type), reject an accompanying Options payload whose members are public-only (notably Export) with the ValidationException above, before any certificate state is created.
Traces: acm__acm-pca.request-certificate-export-option-with-private-ca-rejected.
