# airflow-serverless, amplifyuibuilder, aoss and 7 more ListAWSDefaultServiceQuotas codes return no quota rows

> _Note: this issue was identified against the code base at commit `23d7c3ca3e68cb70ca93342274fc19d1394baa26`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
10 net-new causes, one per AWS ServiceCode whose AWS-default quota set is absent from the emulator's ListAWSDefaultServiceQuotas catalog. The shape of every cause is identical: the call is accepted (HTTP 200) but the returned Quotas list carries none of the rows AWS publishes for that ServiceCode, so every compared element reports `got None`. Each cause is its own catalog gap (a different ServiceCode, a different row set) and each must be closed separately. Related but NOT covering these codes: open issue 20261030T104829Z-service-quotas-listawsdefaultservicequotas-default-catalog-misbinds-and-omits-aws-quota.md, which owns the codes whose rows ARE present but wrong (apigateway, appconfig, application-autoscaling, appmesh, apprunner, ...).

AWS (common to all 10 causes): Smithy ListAWSDefaultServiceQuotas(ServiceCode required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$; MaxResults @range 1..100) returns ListAWSDefaultServiceQuotasResponse with Quotas: list<ServiceQuota> and an optional NextToken; ServiceQuota carries ServiceCode, ServiceName, QuotaArn, QuotaCode, QuotaName, Value (double @range 0..10000000000), Unit, Adjustable (boolean, default false), GlobalQuota (default false), UsageMetric (MetricInfo), Period (QuotaPeriod) and Description (@length 0..350). Modelled errors are AccessDeniedException 403, IllegalArgumentException 400, InvalidPaginationTokenException 400, NoSuchResourceException 404, TooManyRequestsException 429, ServiceException 500 — none of them applies here: AWS answers 200 with the complete AWS-supplied default quota set for the requested ServiceCode. The catalog CONTENT (which QuotaCodes exist and their QuotaName/Value/Unit/Adjustable/GlobalQuota/Period/UsageMetric/Description) is not stated by the model, so it is recorded behavior only: the recordings show, for each ServiceCode below, a non-empty Quotas list of AWS-published rows keyed by QuotaCode. QuotaArn is 'arn:aws:servicequotas:<region>::<ServiceCode>/<QuotaCode>' — the region and account part are environment values, not requirements; the ServiceCode/QuotaCode tail is.

Emulator (common): HTTP 200 with a Quotas list that does not contain the recorded rows at all — the replay reports every expected index as `missing (expected {...}, got None)`.

Why (common): a client enumerating an account's AWS defaults (a quota-reporting or pre-flight capacity tool, or anything that resolves a QuotaCode before ListServiceQuotas/GetServiceQuota/RequestServiceQuotaIncrease) sees the service as having no limits at all. There is no error to branch on, so the client silently treats 'no quota rows' as 'nothing to check' instead of failing — the opposite of AWS behavior.

Fix (common): the service-quotas crate's ListAWSDefaultServiceQuotas handler and the static default-quota catalog it reads. The catalog needs an entry set for each ServiceCode below, with every modelled ServiceQuota member populated per row; the handler's paging over that set is unchanged.
