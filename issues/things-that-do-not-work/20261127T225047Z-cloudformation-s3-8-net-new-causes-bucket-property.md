# cloudformation + s3: 8 net-new causes — bucket property validation never runs, declared configurations are not applied, the resource read nulls or omits properties, lifecycle filters are not And-wrapped, BucketName prefixes misname and never replace, access-point attributes are wrong, Outputs lose OutputValue, and dropping system tags is allowed

> _Note: this issue was identified against the code base at commit `37bf0949a3a203e7d1b7ebeb80108d58d67e6afd`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateChangeSet

## Description
Eight net-new causes in CloudFormation's S3 resource surface.

Cause 1 of 8: CloudFormation's own property validation never runs for AWS::S3::Bucket / AWS::S3::AccessPoint, so off-enum, over-length, non-numeric and off-pattern values are accepted.
AWS: a schema violation makes CreateChangeSet settle (Status FAILED, ExecutionStatus UNAVAILABLE) and CreateStack fail the resource before S3 is touched, with one VALIDATION_ERROR OperationEvent per violation whose ValidationPath is `/Resources/<LogicalId>/Properties/<member path>` and whose reason names the member and the allowed set — e.g. `Disabled is not a valid enum value. Supported values: [Enabled, Suspended]` for VersioningConfiguration.Status (fixed text: `<value> is not a valid enum value. Supported values: [<list>]`; the value comes from the template and the list from the schema). The violations exercised are schema facts: VersioningConfiguration.Status, LifecycleConfiguration rule Status, TransitionDefaultMinimumObjectSize, ObjectOwnership, IntelligentTieringConfiguration Status, ServerSideEncryption SSEAlgorithm, AccessControl canned-ACL spelling (the template enum is PascalCase, not the wire form `private`), RoutingRule/RedirectAllRequestsTo Protocol (http|https only), BucketNamespace, MetadataTableConfiguration state, lifecycle rule Id max 255, ObjectSizeLessThan/GreaterThan numeric-string form and max 20 digits, AccessPoint BucketAccountId 12 digits, and the blocked-encryption-type enum.
Emulator: each settles ('CREATE_COMPLETE','AVAILABLE') or CREATE_COMPLETE/UPDATE_FAILED-at-the-resource, and the VALIDATION_ERROR list is empty — one of them reaches the bucket resource and fails there instead of being refused pre-provision.
Why: a caller gets a green change set and a green stack for a template real CloudFormation refuses, so an invalid bucket configuration is deployed and the violation surfaces only later; a reviewer reading DescribeEvents sees no property diagnosis at all.
Fix: CloudFormation's pre-provision property-validation stage for the AWS::S3::* resource schemas and the VALIDATION_ERROR OperationEvent emission.

Cause 2 of 8: declared bucket configurations are accepted but never applied to the bucket. AWS: AccessControl LogDeliveryWrite grants the log-delivery group WRITE and READ_ACP in GetBucketAcl; ObjectLockEnabled makes GetObjectLockConfiguration return the configuration with the template's default retention; AbacStatus Enabled reads back Enabled; and BlockedEncryptionTypes is empty after a create that blocks nothing and gates new SSE-C uploads only after the update that sets it. Emulator: the ACL holds only the owner's FULL_CONTROL grant, GetObjectLockConfiguration is refused `ObjectLockConfigurationNotFoundError`, AbacStatus reads Disabled, and the blocked list already contains ['SSE-C'] right after create. Why: these are security controls. A caller that encodes object-lock retention, a log-delivery ACL, ABAC or an encryption-type block in a template believes the control is live when it is not (or is live when it should not be). Fix: the AWS::S3::Bucket handler's create/update — carry each sub-configuration to the bucket state instead of only recording it on the resource.

Cause 3 of 8: the resource/drift read of AWS::S3::Bucket nulls or omits properties. AWS: the read model reports Arn and BucketName for a created bucket, carries LifecycleConfiguration in the property sets, and DetectStackResourceDrift answers include a PropertyDifferences member. Emulator: Arn is null, BucketName is null, the LifecycleConfiguration key is absent (KeyError 'LifecycleConfiguration') and PropertyDifferences is absent (KeyError 'PropertyDifferences'). Why: a drift gate or a resource read that consumes these keys raises rather than reporting, and a caller cannot discover the bucket's ARN or name from the stack resource. Fix: the AWS::S3::Bucket read/drift projection — populate read-only attributes and always emit the modelled drift members.

Cause 4 of 8: a lifecycle rule whose filter combines an empty Prefix with an object-size bound is not And-wrapped. AWS: S3 requires more than one filter predicate to be nested under `And`, so GetBucketLifecycleConfiguration reports `{'And': {'Prefix': '', 'ObjectSizeLessThan': N}}` (or the GreaterThan form). Emulator: the rule reads back as a bare `{'ObjectSizeLessThan': N}`. Why: a client that round-trips the lifecycle configuration back into PutBucketLifecycleConfiguration, or that inspects the And block to learn the rule's scope, reads a shape S3 never returns. Fix: the lifecycle filter serialisation in the AWS::S3::Bucket handler / GetBucketLifecycleConfiguration.

Cause 5 of 8: BucketName prefix handling misnames the bucket and a prefix change is not a replacement. AWS: the generated bucket name derives from the declared prefix (the recorded form is 55 characters built from the prefix), a change of the prefix is planned with Replacement True and creates a new bucket from the NEW prefix while the first bucket is named from the first prefix. Emulator: the first bucket is not named from the first prefix, the generated name is 48 characters rather than the 55-character form, and the change is planned ('Modify', Replacement 'False', RequiresRecreation 'Never'). Why: the bucket name is the resource's identity; a caller cannot predict or recognise the bucket it deployed, and a change set hides the replacement of a bucket. Fix: the generated-name construction and the create-only classification of BucketName/BucketNamespace in the AWS::S3::Bucket handler.

Cause 6 of 8: AWS::S3::AccessPoint read-only attributes are wrong. AWS: Fn::GetAtt Alias resolves to the alias S3 minted (never the declared alias, bucket or point name); Fn::GetAtt Arn has the shape `arn:<partition>:s3:<region>:<account>:accesspoint/<name>` (one word, `accesspoint`); and NetworkOrigin is set by S3 from the presence of VpcConfiguration — `Internet` when there is none, `VPC` when there is one — regardless of any declared value. Emulator: Alias is the declared value, the Arn uses `access-point/<name>`, and NetworkOrigin reads `VPC` for a point with no VpcConfiguration. Why: the access-point ARN and alias are what clients address; a wrong ARN segment makes every request built from the output fail, and a NetworkOrigin of VPC on an internet point misreports the point's reachability. Fix: the AWS::S3::AccessPoint handler's attribute projection and ARN construction.

Cause 7 of 8: stack Outputs are returned without an OutputValue. AWS: every Stacks[].Outputs entry carries OutputKey and OutputValue. Emulator: the OutputValue member is absent (KeyError 'OutputValue') for access-point-derived outputs. Why: every consumer of the output breaks. Fix: output resolution/serialisation for Fn::GetAtt attributes of AWS::S3::AccessPoint.

Cause 8 of 8: PutBucketTagging that drops CloudFormation's system tags succeeds. AWS: a tagging call on a stack-managed bucket that omits the aws:cloudformation:* tags is refused — the caller may not mutate system tags — and the live tag set is unchanged. Emulator: the call returns HTTP 204 and the system tags are gone. Why: the system tags are how CloudFormation attributes and reconciles a resource; a client can silently detach a bucket from its stack. Fix: the system-tag guard in PutBucketTagging / the bucket tagging state.
