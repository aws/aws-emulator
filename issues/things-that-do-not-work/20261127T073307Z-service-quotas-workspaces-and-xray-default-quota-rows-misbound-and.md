# workspaces and xray default-quota rows misbound and Descriptions dropped in service-quotas catalog

> _Note: this issue was identified against the code base at commit `33932bf6f81e8cc72c4071b6c64638fb9bd78d71`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
ListAWSDefaultServiceQuotas

## Description
Shared fault: the emulator's ListAWSDefaultServiceQuotas default-quota catalog pairs a QuotaCode with the WRONG quota's metadata, drops Description on rows that have one, and carries over the wrong Period/UsageMetric/Unit/Adjustable for the row it mispaired. The status and envelope are correct (recorded 200, served 200); only the Quotas list body diverges. This issue bundles TWO causes, one per ServiceCode: workspaces and xray. Both must be fixed and re-replayed before it is closed.

General AWS grounding (applies to both causes). Smithy (services/service-com-amazonaws-servicequotas-servicequotasv20190624/smithy-model/com-amazonaws-servicequotas-servicequotasv20190624.json): ListAWSDefaultServiceQuotas(ServiceCode required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$; NextToken @length 0..2048; MaxResults @range 1..100) -> ListAWSDefaultServiceQuotasResponse{Quotas: ServiceQuotaListDefinition, NextToken}, @paginated(items=Quotas); errors AccessDeniedException 403, IllegalArgumentException 400, InvalidPaginationTokenException 400, NoSuchResourceException 404, TooManyRequestsException 429, ServiceException 500. Smithy ServiceQuota members: ServiceCode, ServiceName, QuotaArn, QuotaCode (@pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$), QuotaName, Value (QuotaValue double @range 0..10000000000), Unit, Adjustable (boolean, default false), GlobalQuota (boolean, default false), UsageMetric (MetricInfo{MetricNamespace, MetricName, MetricDimensions, MetricStatisticRecommendation}), Period (QuotaPeriod{PeriodUnit, PeriodValue}), QuotaContext, Description (QuotaDescription @length 0..350). The model fixes the SHAPE but says nothing about the catalog's contents, so the per-quota contents are recorded behavior only: AWS returns, for a given ServiceCode, its published default-quota set in which every QuotaCode carries ITS OWN QuotaName, Description, Value, Unit, Adjustable, Period and UsageMetric. The requirement is the QuotaCode -> metadata pairing and the presence and exact wording of each row's Description; the individual numbers below are quoted only as the recording's examples of a mispairing. No error path is involved: both causes are 200-vs-200 body divergences, so there is no status, error code or error message to reproduce here.

Cause 1 of 2: workspaces (Amazon WorkSpaces). AWS: each workspaces QuotaCode carries its own quota, and a RESOURCE-count quota carries a resource-shaped Period and UsageMetric while an API-rate quota carries an API-shaped one - recorded example: L-9A67B5CB = QuotaName 'Standby WorkSpaces', Description 'The maximum number of Standby WorkSpaces in this account in the current Region.', Period {PeriodUnit MINUTE, PeriodValue 5}, UsageMetric {MetricDimensions Resource 'StandbyWorkSpace'/Type 'Resource', MetricName 'ResourceCount', MetricStatisticRecommendation 'Maximum'}. Further recorded rows carry their own Description: L-40A36AF9 'The maximum number of Graphics.g6.4xlarge WorkSpaces in this account in the current Region.', L-BD784BE1 'The maximum number of Graphics.g6.16xlarge WorkSpaces in this account in the current Region.', L-8C70C791 'The maximum number of General Purpose Value streaming instances that can be used for WorkSpaces Pools in this account in the current Region.', L-63F14199 'The maximum number of Graphics.g7.2xlarge WorkSpaces in this account in the current Region.', L-F64A92CF 'The maximum number of Graphics.g7.4xlarge WorkSpaces in this account in the current Region.'. Emulator: it serves L-9A67B5CB as 'Rate of DeleteIpGroup requests' with Description 'The maximum number of DeleteIpGroup requests you can make per second in this account in the current Region.', Period {SECOND, 1} and UsageMetric {Resource 'DeleteIpGroup', Type 'API', MetricName 'CallCount', MetricStatisticRecommendation 'Sum'}, and serves L-40A36AF9, L-BD784BE1, L-8C70C791, L-63F14199 and L-F64A92CF with Description missing (got None). Roughly 45 workspaces QuotaCodes diverge the same way on Adjustable/Description/Period/QuotaName/UsageMetric/Value (including L-011B3C20, L-0798A2C9, L-07C6D3A5, L-0B7D5CA2, L-0E312A12, L-158CE743, L-18CE281C, L-18F1706C, L-254B485B, L-2F7BEDD3, L-337DA39D, L-34278094, L-34D55C89, L-3AC69A9E, L-465DA8AF, L-5782CB4D, L-6E205E73, L-70A02F17, L-843E43DA, L-925915DC, L-9A67B5CB, L-9C1F7EB2, L-BCACAEBC, L-BE9A8466, L-C266A5F4, L-C76331EA, L-D34D6523, L-D6CFBE96, L-E2CD2905, L-EEB759DE, L-EF6817EC, L-F61D0B79, L-F7854FE2). Note the systematic kind-flip: a RESOURCE-count row (ResourceCount/Maximum over a 5-minute period) is served as an API-rate row (CallCount/Sum over 1 second), which is the signature of a shifted catalog index rather than of individually wrong values. Why: a fleet-sizing client that reads its Standby WorkSpaces or Graphics-bundle headroom by QuotaCode gets HTTP 200 carrying an API throttle rate, and because Period and UsageMetric are flipped to the API shape it cannot even detect that the value is not a resource count; any CloudWatch AWS/Usage query built from the returned dimensions then returns no data, so the client sees zero usage against the wrong quota. Fix: the QuotaCode-to-row pairing and the Description/Period/UsageMetric population in the service-quotas default-quota catalog data behind the ListAWSDefaultServiceQuotas handler, for ServiceCode 'workspaces'. Traces: service-quotas-catalog-list-aws-default-service-quotas-workspaces#task#1.

Cause 2 of 2: xray (AWS X-Ray). AWS: recorded examples - L-3B8EFF88 = QuotaName 'Trace document size (lower limit)', Description 'The maximum size of a trace document.', Unit 'Kilobytes', Adjustable false, Value 100; L-7F259013's Description reads 'The maximum number of groups per account.'; L-8C0C998A carries 'The maximum number of custom sampling rules per region.', L-DB51D338 'The maximum number of tags per custom sampling rule.', L-428FB8E0 'The maximum size of a trace document.', L-998BFF16 'The number of days to retain trace and service map data.' and L-5DB17969 'The number of days to update recorded data at no additional cost.'. Emulator: it serves L-3B8EFF88 as 'Rate of GetSamplingRules requests' with Description 'The maximum number of GetSamplingRules requests you can make per second in this account in the current Region.', Unit 'None', Adjustable true and Value 10; it re-words L-7F259013's Description to '...in this account in the current Region.'; and it serves L-8C0C998A, L-DB51D338, L-428FB8E0, L-998BFF16 and L-5DB17969 with Description missing (got None). Why: a tracing agent that checks the trace-document size limit by QuotaCode reads 10 with Unit 'None' instead of 100 Kilobytes, so it either truncates valid segments or emits segments AWS rejects; Adjustable flipped to true invites an increase request on a hard document-size limit; and with Description absent the retention and sampling-rule rows cannot be rendered or diffed against AWS's documentation. Fix: the QuotaCode-to-row pairing, the Unit and Adjustable fields and the Description population/wording in the service-quotas default-quota catalog data for ServiceCode 'xray'. Traces: service-quotas-catalog-list-aws-default-service-quotas-xray#task#1.
