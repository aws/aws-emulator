# appconfig: 3 causes — a rolling deployment is never partial on the data plane, and StopExperimentRun neither refuses during a rollout nor words its not-found message as AWS does

> _Note: this issue was identified against the code base at commit `af007de286377294faf8721f963c7a04ad7dcdf8`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
StopExperimentRun

## Description
Three independent net-new defects in the emulator's AppConfig deployment/experiment-run surface, found by replaying the behavioral suite. None is covered by an open issue: the closest, 20261127T041845Z-appconfig-getdeployment-s-deployment-state-token-is-not.md, is about the Deployment$State token value, and the deployments below do reach their terminal state — these failures are about what the data plane serves and what StopExperimentRun does.

Cause 1 of 3 — a rolling deployment is all-or-nothing on the data plane, never a percentage of sessions (failing check: appconfig.exponential-growth-type-advances-in-powers-of-the-growth-factor).
AWS: a deployment advances through a percentage grid derived from the strategy's GrowthFactor/GrowthType (Smithy: CreateDeploymentStrategy GrowthFactor, GrowthType enum LINEAR|EXPONENTIAL; Deployment$PercentageComplete, range 0-100). While PercentageComplete is strictly between 0 and 100, the configuration data plane (appconfigdata StartConfigurationSession + GetLatestConfiguration) serves the NEW configuration version to approximately that percentage of independent sessions and the PREVIOUS version to the rest — bucketing is per session, so both versions are in service simultaneously mid-rollout, and after the deployment reaches COMPLETE every session gets the new version. Documented for deployment strategies (appconfig-creating-deployment-strategy).
Emulator: with an EXPONENTIAL strategy (GrowthFactor=10, DeploymentDurationInMinutes=4) rolling out hosted version 2 over version 1, every session sampled while 0 < PercentageComplete < 100 was served the OLD bytes: across 8 mid-rollout sessions only version 1's document was ever returned, so the new version reached none of the fleet until the deployment flipped terminal. The rollout is a step counter with no effect on what GetLatestConfiguration resolves.
Why: a client validating a canary/progressive rollout (sampling the data plane while a deployment is in flight, or asserting that a percentage of hosts has picked up the new flags) sees a step function at the end of the deployment instead of a gradual rollout. Any test or tool that measures exposure during a rollout, or that relies on the old version remaining in service until the rollout advances, draws the wrong conclusion.
Fix: the appconfigdata data-plane configuration resolution (the code that picks which hosted configuration version a session is served) must consult the environment's in-progress deployment and bucket the session by the deployment's current PercentageComplete, rather than returning the last COMPLETE deployment's version until the rollout ends.
Traces: appconfig.exponential-growth-type-advances-in-powers-of-the-growth-factor (assertion: "the rollout was not partial — across 8 mid-rollout sessions only [b'{\"tier\":\"one\"}'] was ever served").

Cause 2 of 3 — StopExperimentRun succeeds while the environment has a deployment in flight, instead of refusing with ConflictException (failing check: appconfig.stop-experiment-run-during-deployment-conflict-rejected).
AWS: StopExperimentRun models ConflictException with HTTP 409 (Smithy: StopExperimentRun errors BadRequestException 400, ConflictException 409, ResourceNotFoundException 404, InternalServerException 500). Stopping an experiment run drives a deployment of the environment, so while that environment already has a deployment rolling out the call is refused 409 ConflictException and the run is left RUNNING with no EndedAt. Recorded message, whose fixed text is "currently has a state of DEPLOYING. The current deployment must finish before a new deployment can be started." plus the service's call summary, with the environment id taken from the request's environment and the request id generated per call: "Environment <environment-id> currently has a state of DEPLOYING. The current deployment must finish before a new deployment can be started. (Service: AmazonAppConfig; Status Code: 409; Error Code: ConflictException; Request ID: <uuid>; Proxy: null)".
Emulator: the call returns HTTP 200 with a full ExperimentRun body and Status 'DONE' (ExposurePercentage 0.0, EndedAt stamped), even though a 20-minute/GrowthFactor-10 deployment of the same environment was started moments earlier and is still DEPLOYING. No conflict check against the environment's state exists on this path.
Why: a client that models the real mutual exclusion between a deployment and an experiment-run transition (retry-on-409, or asserting the run survives the refusal) sees the run terminated instead. State diverges permanently: the run is DONE on the emulator and RUNNING on AWS, so every later assertion about it is wrong.
Fix: StopExperimentRun's handler/validation must check the target environment's state before mutating the run and return ConflictException (409) with the message above when a deployment of that environment is in progress, leaving the run's Status and EndedAt untouched.
Traces: appconfig.stop-experiment-run-during-deployment-conflict-rejected.

Cause 3 of 3 — StopExperimentRun's ResourceNotFoundException for an unknown run number is worded differently from AWS's (failing check: appconfig.stop-experiment-run-unknown-run-number-not-found-rejected).
AWS: ResourceNotFoundException, HTTP 404 (Smithy: StopExperimentRun errors include ResourceNotFoundException 404). Recorded message, fixed text "Experiment run " / " not found for experiment definition " / " in application " / " for account " / "." with the run number, the experiment-definition id and application id from the request and the account id from the caller: "Experiment run <run> not found for experiment definition <definition-id> in application <application-id> for account <account-id>."
Emulator: the code is right but the message is a different template: "Experiment run with Experiment Definition Id <definition-id>, Application Id <application-id>, and Experiment Run <run> could not be found for account <account-id>."
Why: a client or operator matching on the message text (log scraping, error-classification rules, golden-output tests) does not recognise the emulator's refusal, and the rendered text does not match what AWS's SDKs surface.
Fix: the StopExperimentRun handler's not-found error construction must emit AWS's template; the status and code are already correct.
Traces: appconfig.stop-experiment-run-unknown-run-number-not-found-rejected.

## Evidence
Cause 1 — expected: with 0 < PercentageComplete < 100 during an EXPONENTIAL (GrowthFactor=10, 4-minute) rollout of hosted version 2 over version 1, mid-rollout sessions see BOTH versions' exact bytes (no proportion asserted), and all sessions converge on version 2 after COMPLETE. Actual: AssertionError "the rollout was not partial — across 8 mid-rollout sessions only [b'{\"tier\":\"one\"}'] was ever served, so the new version reached either none or all of the fleet instead of a percentage of it".

Cause 2 — expected: ClientError ConflictException, HTTP 409, message "Environment <env-id> currently has a state of DEPLOYING. The current deployment must finish before a new deployment can be started. (Service: AmazonAppConfig; Status Code: 409; Error Code: ConflictException; Request ID: <uuid>; Proxy: null)", with the run still RUNNING and no EndedAt. Actual: HTTP 200 and a success body — AssertionError "expected a refusal, but the call succeeded: {... 'Run': 1, 'Status': 'DONE', 'ExposurePercentage': 0.0, 'StartedAt': ..., 'EndedAt': ..., 'ExperimentDefinitionSnapshot': {...}}" (ids and timestamps are per-run values, not requirements).

Cause 3 — expected: ('ResourceNotFoundException', "Experiment run <run> not found for experiment definition <def-id> in application <app-id> for account <account>."). Actual: ('ResourceNotFoundException', 'Experiment run with Experiment Definition Id <def-id>, Application Id <app-id>, and Experiment Run <run> could not be found for account <account>.') — AssertionError "stop of run 2 answered 'ResourceNotFoundException': 'Experiment run with Experiment Definition Id 4pwhmf2, Application Id ho65pb1, and Experiment Run 2 could not be found for account 000000000000.'"

## Steps to Reproduce
Cause 1: create an application, environment and hosted (LocationUri="hosted") configuration profile; create hosted configuration versions 1 and 2 with distinct bodies; deploy version 1 with a 0-minute/GrowthFactor-100 strategy and wait for COMPLETE; create a strategy with DeploymentDurationInMinutes=4, GrowthFactor=10, GrowthType=EXPONENTIAL, FinalBakeTimeInMinutes=0; StartDeployment of version 2 with it; while GetDeployment reports 0 < PercentageComplete < 100, repeatedly StartConfigurationSession + GetLatestConfiguration from fresh sessions and collect the bodies. Expect both version 1's and version 2's bytes to appear; the emulator returns only version 1's.

Cause 2: with the same application/environment/hosted FeatureFlags profile and two hosted versions, deploy version 1 with a 0-minute strategy and wait for the environment to read ReadyForDeployment; CreateExperimentDefinition on that profile/environment and StartExperimentRun; StartDeployment of version 2 with a DeploymentDurationInMinutes=20, GrowthFactor=10 strategy; immediately call StopExperimentRun for the running run. Expect ConflictException 409; the emulator returns 200 with Status DONE.

Cause 3: after StartExperimentRun returns run N, call StopExperimentRun with Run=N+1. Expect ResourceNotFoundException with the message "Experiment run N+1 not found for experiment definition <def-id> in application <app-id> for account <account>."; compare with the emulator's wording.
