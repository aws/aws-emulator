# bedrock-agentcore__stepfunctions: 4 causes — Step Functions connector targets advertise no tools, their tool schemas are empty, an out-of-connector operation is accepted, and the Express .waitForTaskToken refusal message loses a space

> _Note: this issue was identified against the code base at commit `461e190cfbed2a60f922688bafee74a0fd88eec8`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
CreateGatewayTarget

## Description
Four net-new root causes across the AgentCore gateway's Step Functions connector surface, each numbered with its own failing checks.

Cause 1 of 4: a gateway target backed by the built-in Step Functions connector contributes no tools — tools/list is empty and every tools/call is an unknown tool.
AWS: recorded behavior only (the connector projection is not stated in the model). The recording shows a connector target (targetConfiguration.mcp.connector.source.connectorId='states') projected into tools/list as one tool per configured operation, named '<targetName>___<OperationName>' — e.g. the full set ['wf___DescribeExecution', 'wf___DescribeStateMachine', 'wf___GetExecutionHistory', 'wf___ListExecutions', 'wf___SendTaskFailure', 'wf___SendTaskHeartbeat', 'wf___SendTaskSuccess', 'wf___StartExecution', 'wf___StartSyncExecution', 'wf___StopExecution'] for a target named 'wf' — and tools/call on such a name performing the Step Functions call under the gateway role (including the role-scope denials, the Express/Standard restrictions on ListExecutions and StartSyncExecution, and the raw API JSON a DescribeStateMachine tool returns).
Emulator: tools/list answers [] for connector targets, and tools/call answers JSON-RPC {'code': -32602, 'message': 'Invalid params: this gateway serves no tool named <target>___<Operation>'}; the checks that index the absent tool or its result fail with KeyError 'result' / KeyError '<target>___ListExecutions'.
Why: the entire Step Functions connector surface is unreachable — an agent can neither discover nor invoke any workflow operation through a gateway, and none of the authorization or workflow-type refusals can be reached.
Fix: the connector-target tools/list projection and tools/call dispatch in the gateway MCP data plane.
Traces: bedrock-agentcore__stepfunctions.gateway-connector-describe-execution-all-data-includes-input-and-output, -get-execution-history-records-every-state, -send-task-success-resumes-activity-wait, -start-execution-agent-state-machine-arn-rejected, -start-execution-runs-pinned-state-machine, -tools-list-advertises-each-operation-without-the-pin, bedrock-agentcore__stepfunctions.gateway-states-describe-execution-denied-by-state-machine-scoped-grant, -describe-execution-outside-role-scope-denied, -describe-execution-withholds-data-unless-all-data, -describe-state-machine-tool-returns-raw-api-json, -list-executions-tool-rejected-for-express-workflow, -start-execution-rejects-agent-supplied-state-machine, -start-execution-returns-arn-of-pinned-run, -start-sync-execution-returns-express-result, -start-sync-execution-tool-rejected-for-standard-workflow, bedrock-agentcore__stepfunctions.gateway-sync-execution-on-standard-pin-rejected, -returns-status-output-and-timing, bedrock-agentcore__stepfunctions.states-connector-list-executions-on-express-rejected, -list-executions-status-filter-outside-enum-rejected, -send-task-success-resumes-paused-execution, -start-execution-runs-pinned-state-machine, -start-execution-without-role-permission-denied.

Cause 2 of 4: where a connector tool is looked up, its advertised input schema declares nothing.
AWS: recorded behavior only: a connector tool's inputSchema declares exactly the operation's agent-supplied members — DescribeExecution requires only executionArn, and a StartExecution tool whose state machine is pinned by the target configuration advertises only 'input' (the pinned stateMachineArn is not an agent-supplied property).
Emulator: the schema carries no required list and no properties ('DescribeExecution\'s tool schema requires None'; 'the pinned StartExecution tool advertises []').
Why: an agent reading the tool schema cannot tell which arguments to send, and the pin that must not be overridable is not expressed in the schema at all.
Fix: inputSchema generation for connector tools (required members, and omission of the pinned parameters) in the gateway's connector projection.
Traces: bedrock-agentcore__stepfunctions.gateway-describe-execution-defaults-to-metadata-only, bedrock-agentcore__stepfunctions.gateway-pinned-state-machine-override-rejected.

Cause 3 of 4: CreateGatewayTarget accepts a connector configuration naming an operation the connector does not expose.
AWS: recorded behavior only: a connector target whose configurations name an operation outside the connector's operation set (here UpdateStateMachine for the 'states' connector) is refused at create time.
Emulator: the call answers HTTP 202 with status CREATING and echoes the out-of-connector configuration back ('expected a refusal, but the call succeeded: {... 'name': 'UpdateStateMachine', 'parameterValues': {'stateMachineArn': …}}').
Why: a target is created that can never serve the operation it declares, so a configuration error surfaces (if at all) only when an agent calls the tool.
Fix: validate each configuration name against the connector's operation set in the CreateGatewayTarget handler.
Traces: bedrock-agentcore__stepfunctions.gateway-connector-target-rejects-an-operation-outside-the-connector.

Cause 4 of 4: the InvalidDefinition message for an Express state machine using .waitForTaskToken is rendered with one space where AWS emits two.
AWS: recorded behavior only for the exact text: CreateStateMachine for an EXPRESS definition whose Task Resource ends in '.waitForTaskToken' is refused InvalidDefinition with "Invalid State Machine Definition: 'SCHEMA_VALIDATION_FAILED: Express state machine does not support '.waitForTaskToken' service integration  at /States/<StateName>/Resource'" — fixed text with two spaces before 'at', and the JSON pointer naming the offending state from the submitted definition.
Emulator: the same code and message but with a single space ('service integration at /States/AwaitApproval/Resource').
Why: a client matching the refusal text (or diffing it against AWS's recorded message) does not recognise the error; the code is right, the rendered message is not.
Fix: the InvalidDefinition message template in the CreateStateMachine definition validator.
Traces: bedrock-agentcore__stepfunctions.express-callback-definition-rejected-gateway-token-resumes-standard.
