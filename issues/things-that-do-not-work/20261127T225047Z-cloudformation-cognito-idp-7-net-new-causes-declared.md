# cloudformation + cognito-idp: 7 net-new causes — declared read-only properties roll stacks back, create-only updates are refused as NotImplemented, a rename replaces the pool, MFA cannot be enabled, Precedence is not validated, and the ID token issuer is the serving host

> _Note: this issue was identified against the code base at commit `37bf0949a3a203e7d1b7ebeb80108d58d67e6afd`. If you are an issue fixer working on this, the code base you are currently working in can have drifted, so you might need to trace the issue back to the current code base._

## Operation
UpdateUserPool

## Description
Seven net-new causes in CloudFormation's Cognito user-pool surface.

Cause 1 of 7: a template that supplies a value for a READ-ONLY Cognito property rolls the stack back instead of ignoring the value. AWS: read-only attributes of AWS::Cognito::UserPoolClient (ClientSecret) and AWS::Cognito::UserPool (ProviderName) are not inputs — a template that sets them is accepted, the value is discarded, the resource is created with the service-assigned value and the stack reaches CREATE_COMPLETE (recorded behaviour only). Emulator: both stacks settle ROLLBACK_COMPLETE. Why: a template generated by CDK/SAM or copied from a DescribeStack read often carries read-only members; against the emulator such a deploy fails outright. Fix: the Cognito resource handlers' input projection — strip read-only members before validation instead of refusing them. Checks: cfn-user-pool-client-declared-client-secret-ignored-for-generated, cfn-user-pool-client-hash-under-declared-secret-rejected, cfn-user-pool-declared-provider-name-ignored-for-service-value.

Cause 2 of 7: an ID token minted by the emulator carries an `iss` claim built from the host:port it is reached on. AWS: the issuer of a Cognito ID token is `https://` + the pool's ProviderName, i.e. `https://cognito-idp.<region>.amazonaws.com/<userPoolId>` — the same value Fn::GetAtt <pool>.ProviderName resolves to. Emulator: `iss` is `https://<emulator-host>:<port>/<userPoolId>`, which is not derived from ProviderName at all. Why: every OIDC verifier pins the issuer to the provider URL it discovered; a token whose iss is the transport address fails validation in any library. (The serving host is environment-specific and is not the requirement — the requirement is that iss is derived from the pool's ProviderName.) Fix: the token minting in the Cognito auth handlers (AdminInitiateAuth/InitiateAuth) must build iss from the pool's provider name. A separate open issue, 20261113T003524Z-cloudformation-cognito-idp-4-net-new-causes-cognito.md, owns the OIDC discovery-document issuer; this check covers the issued token. Checks: cfn-user-pool-client-getatt-secret-signs-admin-password-auth.

Cause 3 of 7: an update that changes a CREATE-ONLY property of a Cognito child resource is refused as not implemented instead of replacing the resource. AWS: changing UserPoolId on AWS::Cognito::UserPoolClient, AWS::Cognito::UserPoolGroup or AWS::Cognito::UserPoolResourceServer requires replacement — CloudFormation creates the resource in the new pool, repoints the logical id and deletes the original, and the stack reaches UPDATE_COMPLETE. Emulator: the resource reports UPDATE_FAILED with `NotImplemented: this emulator does not change the properties of an existing AWS::Cognito::UserPoolClient in place; the resource was left as it is.` and the stack settles UPDATE_ROLLBACK_COMPLETE. Why: a caller moving an app client, group or resource server between pools cannot deploy at all, and the stack is left in a rolled-back state. Fix: the Cognito resource handlers' update path — a create-only property difference must take the replace branch rather than returning NotImplemented. Checks: cfn-user-pool-client-moved-to-another-pool-is-replaced, cognito-user-pool-group-pool-move-with-generated-name-removes-old-group, deploy-resource-server-user-pool-change-recreates-server-and-orphans-original.

Cause 4 of 7: renaming an AWS::Cognito::UserPool replaces the pool. AWS: UserPoolName is a mutable property; the update is applied in place with UpdateUserPool, Ref keeps resolving to the same us-<region>_<id> pool id and the pool keeps its users. Emulator: Ref changes from one pool id to another, i.e. a new pool was created and the users of the original are gone. Why: a cosmetic rename silently destroys every user in the pool. Fix: the AWS::Cognito::UserPool handler's update classification — UserPoolName must be an in-place (non-replacing) property. Checks: cfn-user-pool-rename-updates-in-place-and-keeps-its-users.

Cause 5 of 7: turning optional TOTP MFA on for an existing pool is refused. AWS: MfaConfiguration OPTIONAL with software-token MFA can be enabled on an existing user pool through a stack update; the stack reaches UPDATE_COMPLETE. Emulator: the resource reports `Resource handler returned message: "Cannot turn MFA functionality ON, once the user pool has been created." (RequestToken: <token>, HandlerErrorCode: InvalidRequest)` and the stack settles UPDATE_ROLLBACK_COMPLETE. Why: a caller hardening an existing pool cannot do it through CloudFormation. Fix: the AWS::Cognito::UserPool handler's update path / SetUserPoolMfaConfig call — drop the create-time-only guard on MFA. Checks: cfn-user-pool-update-turns-on-optional-totp-mfa.

Cause 6 of 7: a negative Precedence on AWS::Cognito::UserPoolGroup produces no property-validation event. AWS: the resource schema bounds Precedence at a minimum of 0, so CloudFormation fails the resource during its own property validation and DescribeEvents carries exactly one VALIDATION_ERROR event for the Group logical id. Emulator: zero VALIDATION_ERROR events are emitted. Why: a caller that reads DescribeEvents to find which property failed gets nothing to report. Fix: the AWS::Cognito::UserPoolGroup schema validation and the VALIDATION_ERROR event emission. Checks: cognito-user-pool-group-negative-precedence-rejected-rollback.

Cause 7 of 7: a template whose Ref names an undeclared resource is refused with the wrong ValidationError. AWS: unresolved template references are diagnosed before resource types are matched, so CreateStack answers ('ValidationError', 'Template format error: Unresolved resource dependencies [<LogicalId>] in the Resources block of the template'). Emulator: answers ('ValidationError', 'Template format error: Unrecognized resource types: [AWS::Cognito::Terms]'), i.e. the unknown-type check runs first and masks the dependency error. Fixed text: `Template format error: Unresolved resource dependencies [` ... `] in the Resources block of the template`; the variable part is the list of unresolved logical ids from the template. The open issue 20261109T124858Z-cloudformation-cognito-idp-4-net-new-causes-cfn.md owns AWS::Cognito::Terms not being registered; it does not cover this validation ordering. Fix: CloudFormation's template validation order. Checks: deploy-terms-ref-to-undeclared-client-rejected.

## Steps to Reproduce
Cause 1: CreateStack with an AWS::Cognito::UserPoolClient whose Properties set ClientSecret, and separately an AWS::Cognito::UserPool whose Properties set ProviderName — expect CREATE_COMPLETE with the declared value ignored.
Cause 2: deploy a user pool + client with GenerateSecret true, AdminInitiateAuth with ADMIN_USER_PASSWORD_AUTH and the SECRET_HASH, then decode the ID token's iss claim and compare with 'https://' + Fn::GetAtt <pool>.ProviderName.
Cause 3: deploy a UserPoolClient / UserPoolGroup / UserPoolResourceServer in pool A, then UpdateStack pointing UserPoolId at pool B — expect UPDATE_COMPLETE with the resource replaced.
Cause 4: deploy a UserPool, then UpdateStack changing only UserPoolName — expect Ref unchanged and the pool's users intact.
Cause 5: deploy a UserPool without MFA, then UpdateStack setting MfaConfiguration OPTIONAL with software-token MFA — expect UPDATE_COMPLETE.
Cause 6: CreateStack with an AWS::Cognito::UserPoolGroup whose Precedence is negative, then DescribeEvents and count VALIDATION_ERROR events for the group.
Cause 7: CreateStack with a template whose resource Refs a logical id that is not declared — expect the 'Unresolved resource dependencies' ValidationError.
