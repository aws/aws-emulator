## Description
9 net-new causes. For these ServiceCodes the emulator DOES serve a default-quota list, but the list is partial or mis-bound: specific AWS QuotaCodes are absent, the Description member is omitted on rows that are present, and on some rows Adjustable is inverted. Each cause is a distinct ServiceCode's catalog defect and must be closed separately. The same defect class for other ServiceCodes is owned by open issue 20261030T104829Z-service-quotas-listawsdefaultservicequotas-default-catalog-misbinds-and-omits-aws-quota.md (apigateway, appconfig, application-autoscaling, appmesh, apprunner, athena, autoscaling, backup, codecommit, codedeploy, ...); that issue does NOT carry a replay key for any of the nine codes below, so they are filed here.

AWS (common to all 9 causes): Smithy ListAWSDefaultServiceQuotas(ServiceCode required, @length 1..63, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,63}$) answers 200 with Quotas: list<ServiceQuota>. ServiceQuota members (per the model): ServiceCode, ServiceName, QuotaArn, QuotaCode (@length 1..128, @pattern ^[a-zA-Z][a-zA-Z0-9-]{1,128}$), QuotaName, Value (double @range 0..10000000000), Unit, Adjustable (boolean, 'Indicates whether the quota value can be increased', default false), GlobalQuota (default false), UsageMetric (MetricInfo), Period (QuotaPeriod) and Description (@length 0..350, 'The quota description'). AWS returns one row per published default quota for the ServiceCode, each row complete: QuotaName, Value, Unit, Adjustable, Description and — for rate quotas — Period and UsageMetric all belong to the SAME QuotaCode. Which codes exist and their field values are not stated by the model (recorded behavior only); the recordings are the reference. The binding between QuotaCode and the rest of the row is the requirement here, not any single recorded number.

Emulator (common): HTTP 200, but (a) whole rows for specific QuotaCodes are absent from Quotas, (b) rows that are present carry no Description at all (`Description: missing ... got None`), and (c) some rows report an Adjustable/QuotaName/Value triple belonging to a different quota, i.e. the row's identity (QuotaCode) and its payload are bound to different quotas.

Why (common): a client resolving a limit by QuotaCode either fails to find it or reads another quota's name and value under it — so it enforces or reports the wrong limit while believing it read the right one, and the quota's documented Description (the text consoles and reports display) is never available. An inverted Adjustable additionally tells the client a fixed quota can be raised (or that an adjustable one cannot), which is what drives whether RequestServiceQuotaIncrease is even attempted.

Fix (common): the service-quotas crate's static default-quota catalog and the ListAWSDefaultServiceQuotas row projection — rows must be keyed by QuotaCode with all of QuotaName/Value/Unit/Adjustable/GlobalQuota/Description (and Period/UsageMetric where AWS publishes them) taken from the SAME catalog entry, and the Description member must be serialized rather than dropped.
